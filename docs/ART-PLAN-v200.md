## 0. 한 줄 진단

**픽셀이 부족한 게 아니라 「밀도」가 없다.**
스프라이트는 색이 6색이고, 타일은 텍스처가 0이고, 무기는 2px이다.
해상도를 올리는 게 아니라 **한 픽셀당 정보량**을 올리는 작업이다.

## 1. 계측 — 지금 무엇이 부족한가

### 1-1. 플레이어

```
직업 4종 · 프레임 5장/직업 (정지·걷기1·걷기2·공격·피격)
전부 22×28px · 11~17색 · 채움 67~72%
```

| 문제 | 근거 |
|---|---|
| **걷기가 2프레임** | 다리 교차만. 상체는 완전 고정 — 뛰는 느낌이 없다 |
| **방향이 좌/우 2방향** | 위·아래로 갈 때도 옆모습. 8방향은커녕 4방향도 아니다 |
| **대시·회피 프레임 없음** | v188에서 회피를 게임의 축으로 세웠는데 **회피 동작 그림이 없다** |
| **피격 1프레임** | 어디서 맞았는지 그림이 말해주지 않는다 |
| **무기가 몸에 그려 넣어져 있다** | 무기 교체·속성 발광이 불가능 |

### 1-2. 몬스터 (1~5층 대표 24종 계측)

```
크기      8×6 ~ 28×24px  — 통일된 픽셀 밀도가 없다
색수      최소 4 / 평균 6.1 / 최대 9   ← 명암 3단계가 실제로는 본색+그늘+아웃라인
```

**중복이 심각하다** (`docs/audit/art-enemy.png` 8배 확대에서 확인):

| 중복 그룹 | 근거 |
|---|---|
| skeleton ≡ boneHeap ≡ archer | 셋 다 22×21 · 7색 · 채움 64% — 같은 몸에 팔레트·소품만 다름 |
| slime ≡ sporeling | 둘 다 26×14 · 8색 · 채움 59% |
| wraith ≡ fireSpirit ≡ necro | 셋 다 26×26 · 5색 · 채움 34~35% — 유령 실루엣 하나에 색만 바뀜 |
| jailer ≡ shaman ≡ brute ≡ stalker | 넷 다 28×24 |

**무기가 판독 불가.** skeleton의 검은 **2px 갈색 막대**, archer의 활은 흰 격자무늬,
shade의 무기는 회색 사선 1개. 보스와 똑같은 문제가 잡몹에도 있다.

### 1-3. 맵 — 가장 심각

`docs/audit/proto-map.png` 위쪽(A)이 지금 화면이다.

| # | 문제 |
|---|---|
| ① | **바닥에 텍스처가 0.** 48px 단색 사각형의 밝기만 조금씩 다르다 → **타일 경계가 격자로 읽힌다** |

## 3. 개편 설계

### 3-1. 해상도 규격 — 「화면 크기는 그대로, 배율을 낮춘다」

지금은 작은 원본을 크게 늘려서(배율 2.7~4.0) 픽셀이 3px 블록으로 뭉갠다.
원본을 키우고 배율을 낮추면 **화면 크기는 같은데 디테일만 늘어난다.**

| 대상 | 현재 원본 | 새 규격 | 화면 크기 | 배율 |
|---|---|---|---|---|
| 플레이어 | 22×28 | **32×40** | 그대로 | 2.0 → 1.4 |
| 잡몹 (소형) | 8~19px | **24×24** | 그대로 | — |
| 잡몹 (중형) | 20~26px | **32×32** | 그대로 | — |
| 정예·미니보스 | 26~28px | **40×40** | 그대로 | — |
| 보스 | 28~34px | **48×48** | 그대로 | 2.7~4.0 → 1.8 |
| 타일 | 없음(단색) | **24×24 텍스처** | 48px | 2.0 |

**색 규격:** 대상마다 **본색 3단(밝음/중간/그늘) + 반사광 1 + 아웃라인 1 = 최소 8색**.
지금 평균 6.1색은 사실상 2단이다.

### 3-2. 플레이어 — 회피가 게임의 축이면 회피에 프레임을 준다

| 항목 | 현재 | 개편 |
|---|---|---|
| 걷기 | 2프레임 (다리만) | **4프레임** — 상체 상하 + 팔 반동 + 망토 흔들림 |
| 방향 | 좌/우 2방향 | **4방향** (앞/뒤/좌/우) — 뒤통수 프레임 추가 |
| 대시 | **없음** | **3프레임** (웅크림 → 늘어남 → 착지) + 잔상 3장 |
| 공격 | 1프레임 | **3프레임** (예비 → 타격 → 여파) |
| 피격 | 1프레임 | **2프레임** + 피격 방향으로 젖혀짐 |
| 무기 | 몸에 그려 넣음 | **분리 레이어** — 교체·속성 발광 가능 |

프레임 총량: 직업당 5장 → **직업당 22장**. 4직업 = 88장. **전부 코드 생성이므로 용량 증가 없음.**

### 3-3. 몬스터 — 실루엣 3계층으로 중복을 깬다

멀리서 봐도 누군지 알아야 한다. `머리` × `몸 비율` × `무기`를 종족마다 확정한다.

| 계층 | 값 |
|---|---|
| 머리 | 두개골 / 투구 / 두건 / 뿔 / 버섯갓 / 부리가면 / 없음(유령) |
| 몸 비율 | 장신 마름 / 보통 / 육중 / 왜소 / 사족 / 부유 |
| 무기 | 검 / 활 / 방패 / 창 / 지팡이 / 낫 / 갈고리 / 없음(맨몸) |

**1~5층 로스터 24종은 이 셋의 조합이 모두 달라야 한다.**
현재 중복 4그룹(skeleton≡boneHeap≡archer, slime≡sporeling, wraith≡fireSpirit≡necro,
jailer≡shaman≡brute≡stalker)을 우선 해체한다.

추가로 **애니메이션 2프레임 → 4프레임**(이동/공격 예비/공격/피격),
그리고 §보스 기획안 §2-2의 **속성색 발광을 무기 레이어에** 입힌다.

### 3-4. 맵 — 타일 시스템 신설

```
타일 종류      바닥 / 벽앞면 / 벽윗면 / 문턱 / 계단 / 균열바닥 / 물 / 빙판 / 불바다 / 독무
층 테마 5종    묘지(갈색·이끼) · 늪(초록·물) · 감옥(회색·쇠) · 소각로(주황·재) · 성소(청보라·대리석)
변주           타일마다 시드 → 균열·이끼·잔해 확률. 같은 그림이 반복되지 않는다
```

**깊이 3계층**
1. **벽 윗면**(밝음) → **앞면**(어두움) → **발밑 그림자** = 높이
2. 캐릭터·구조물 **발밑 타원 그림자** (이미 있음, 강화)
3. **횃불 조명** — 벽에 붙은 광원에서 따뜻한 원뿔. 지형이 읽히는 밝기까지 올린다

**§보스 기획안과의 연결:** §2-1 도형 문법 중 **▦타일**(바닥이 순서대로 무너진다)은
타일 시스템이 있어야 성립한다. 이 작업이 그 전제다.

## 4. 순서 — 보스 기획안(v200~v204) **다음**에 붙인다

보스 표현(v200~v204)이 먼저다. 아트가 아무리 좋아져도 화면에 원만 뜨면 소용없고,
반대로 도형·속성이 잡히면 아트가 그걸 실어 나른다.

| 버전 | 내용 | 검증 |
|---|---|---|
| **v205** | **맵 타일 시스템** — 바닥/벽/조명 3계층. 층 테마 5종 | `frame-audit` 화면 지배 색상 · 평균 밝기 |
| **v206** | **몬스터 1~5층 24종** — 32×32 규격 + 실루엣 3계층 + 4프레임 | 중복 그룹 0 · 무기 판독 |
| **v207** | **플레이어 4직업** — 32×40 + 대시/공격/피격 프레임 + 무기 분리 | 프레임 22장/직업 |
| **v208** | **보스 1~5층 5종** — 48×48 + 무기 분리 레이어 (보스 기획안 §2-5) | 무기 실루엣 중복 0 |

### 지표

| 지표 | 현재 | 목표 |
|---|---:|---:|
| 스프라이트 평균 색수 | 6.1 | **9 이상** |

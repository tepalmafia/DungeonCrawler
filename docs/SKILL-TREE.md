# 스킬 트리 — 기획안

> 대상: `web/3d`
> 상태: **기획안. 구현 전.**
> 전제: `docs/ELEMENTS.md`(속성 4순환) · `docs/FLOORS.md`(9층 3막) ·
> `docs/ITEM-ECONOMY.md`(장비가 힘의 주축) · `docs/BALANCE.md`

---

## 0. 지금 무엇이 문제인가

레벨업이 **아무것도 고르게 하지 않습니다.**

```js
// game/player.js — 지금 레벨업이 하는 일 전부
this.level++;
this.maxHp = 135 + lv * 18;   // 자동
this.dmgMax = ... + lv * 2.4; // 자동
```

숫자만 올라갑니다. 스킬 넷(회전 베기 · 그림자 돌진 · 화염 신성 · 운석 낙하)은
**1레벨부터 전부 열려 있고 9층까지 한 번도 안 바뀝니다.**

그래서 이런 일이 벌어집니다.

| | 지금 |
|---|---|
| 레벨업 순간 | 체력이 차고 숫자가 조금 오른다. **누를 것이 없다** |
| 스킬 | 처음부터 넷 다. 고를 일도 키울 일도 없다 |
| 빌드 | 없다. 두 사람이 9층에서 만나면 **똑같이 싸운다** |

그리고 `tools/growth.js` 실측(`docs/FLOORS.md §7-b-4`)이 짚은 것이 있습니다 —
**레벨은 이미 세 번째 힘이고, 숫자를 더 얹으면 밸런스 밴드가 나빠집니다**
(TTK 밴드 ×1.21 → ×1.55). 그러니 레벨 보상은 **숫자가 아니라 선택**이어야 합니다.
이 문서가 그 자리를 채웁니다.

## 1. 원칙 다섯

### 1-1. 트리가 아니라 **가지**다

「스킬 트리」라고 하면 40칸짜리 격자를 떠올리기 쉽습니다. 그건 이 게임에
안 맞습니다 — 한 판이 20~40분이고 도달 레벨이 **Lv10~13**입니다
(`docs/FLOORS.md §7-b-4` 실측). 40칸을 주면 **한 판에 4분의 1도 못 찍습니다.**

> **한 판에 다 쓸 수 있는 크기여야 합니다.** 포인트 12~15개, 칸 20개 안쪽.

### 1-2. 스킬을 **잠그지 않는다**

「3레벨에 화염 신성 해금」은 하면 안 됩니다. 이 게임은 **한 판이 끝나면
레벨이 사라집니다**(사망 시 1층부터). 매 판 초반 10분을 스킬 하나로
버티게 만들면 그건 성장이 아니라 **벌**입니다.

> 넷은 **처음부터 전부** 열려 있습니다. 트리는 **키우고 바꾸는** 것만 합니다.

### 1-3. 「+5% 피해」는 선택이 아니다

수치만 올리는 칸은 고민 없이 다 찍습니다. 그건 선택지가 아니라 **지연**입니다.

> 모든 칸은 **행동을 바꿔야** 합니다. 「회전 베기가 뒤도 벤다」, 「돌진이 벽에
> 부딪히면 폭발한다」 — 화면에서 다르게 보여야 칸입니다.

### 1-4. 한 스킬에 **양자택일**을 심는다

같은 스킬을 두 방향으로 갈라 놓습니다. 둘 다는 못 찍습니다.

```
화염 신성 ── 확산   반경 +60%, 피해 −30%          (여럿을 흔든다)
          └─ 응축   반경 −25%, 피해 +80% · 장판 2배 (하나를 녹인다)
```

이게 빌드를 만드는 최소 장치입니다. 「무엇을 찍었나」가 아니라
**「무엇을 버렸나」**가 빌드입니다.

### 1-5. 되돌릴 수 있어야 한다 — 단, 값을 치르고

층마다 주력 속성이 바뀌므로(`docs/ELEMENTS.md`) 화염 특화가 7층에서
답이 아닐 수 있습니다. 잘못 찍고 아홉 층을 가는 것은 학습이 아니라 사고입니다.

> **상점에서 「기억의 재」를 사면 포인트를 전부 회수합니다.**
> 값은 층에 비례. 공짜면 매 층 갈아 끼워 선택이 사라집니다.

## 2. 포인트는 어디서 오는가

| 출처 | 개수 | 왜 |
|---|---|---|
| **레벨업** | 레벨당 1 | 지금 비어 있는 자리를 채운다. Lv13이면 12개 |
| **층 보스 처치** | 층당 1 (9개) | 층의 끝에 보상이 하나 더 붙는다 |
| **막 첫 클리어** | 막당 1 (3개) | 3·6·9층. 「막을 넘었다」를 몸으로 알린다 |

한 판 최대 **약 24포인트**. 칸이 20개 안쪽이므로 **끝까지 가면 거의 다 찍습니다** —
그게 맞습니다. 이 게임의 선택은 「무엇을 찍나」가 아니라
**「어느 순서로 찍나」와 「양자택일에서 무엇을 버리나」**입니다.

층이 깊어질수록 포인트가 귀해지지 않아야 합니다. 되돌아가기로 1층을 파밍해도
**포인트는 안 나옵니다**(경험치가 층 배수가 없는 것과 같은 이유 —
`docs/FLOORS.md §7-b-4`). 파밍은 장비, 성장은 진행.

## 3. 구조 — 스킬 4 × 가지 3 + 공용 4

### 3-1. 모양

```
        회전 베기        그림자 돌진       화염 신성        운석 낙하
           │                │                │                │
   1단  ┌──┴──┐        ┌────┴────┐      ┌────┴────┐      ┌────┴────┐
        기본 강화        기본 강화         기본 강화        기본 강화
   2단  ├─────┤        ├─────────┤      ├─────────┤      ├─────────┤
        ▲ 양자택일       ▲ 양자택일        ▲ 양자택일       ▲ 양자택일
   3단  └──┬──┘        └────┬────┘      └────┬────┘      └────┬────┘
         마무리            마무리            마무리           마무리

              ┌───────── 공용 4칸 (스킬 무관) ─────────┐
              │ 마나 회수 · 랜턴 심지 · 죽음의 대가 · 상성 감각 │
              └────────────────────────────────────────┘
```

칸 수 = 4스킬 × (1단1 + 2단2 + 3단1) + 공용 4 = **20칸**, 실제로 찍는 것은
양자택일이 한쪽뿐이므로 **16개**.

### 3-2. 스킬별 가지 (초안)

**회전 베기 (Q · 근접 광역)**

| 단 | 칸 | 무엇이 달라지나 |
|---|---|---|
| 1 | **넓은 호** | 부채꼴 0.78π → 1.15π. 등 뒤 절반까지 |
| 2-A | **연격** | 두 번 휘두른다. 두 번째는 피해 60% |
| 2-B | **가르기** | 한 번이지만 **관통** — 맞은 적의 방어도 30% 무시 |
| 3 | **회오리** | 처치하면 쿨다운 0.35초 감소 (겹친다) |

**그림자 돌진 (W · 이동기)**

| 단 | 칸 | 무엇이 달라지나 |
|---|---|---|
| 1 | **잔상** | 지나간 자리에 그림자가 남아 1.2초간 적 시선을 끈다 |
| 2-A | **관통** | 벽을 한 겹 통과한다 (두께 1칸) |
| 2-B | **충격** | 끝나는 지점에서 폭발 — 반경 3, 넉백 있음 |
| 3 | **연쇄** | 돌진 중 적을 맞히면 쿨다운 40% 즉시 회복 |

**화염 신성 (E · 자기 중심 광역)**

| 단 | 칸 | 무엇이 달라지나 |
|---|---|---|
| 1 | **여진** | 장판 지속 3.4 → 5.5초 |
| 2-A | **확산** | 반경 +60%, 피해 −30% |
| 2-B | **응축** | 반경 −25%, 피해 +80%, 장판 피해 2배 |
| 3 | **재점화** | 장판 위에서 적이 죽으면 그 자리에 작은 장판이 하나 더 |

**운석 낙하 (R · 지정 광역)**

| 단 | 칸 | 무엇이 달라지나 |
|---|---|---|
| 1 | **조준** | 낙하 예고 0.85 → 0.6초 |
| 2-A | **파편** | 본체 피해 −25%, 주변에 작은 운석 셋 추가 |
| 2-B | **직격** | 중심 반경 1.5 안은 피해 2배 (외곽은 그대로) |
| 3 | **여운** | 떨어진 자리가 4초간 **젖은 칸처럼** 적을 느리게 한다 |

### 3-3. 공용 4칸

스킬과 무관하게 **이 게임의 다른 축**에 붙습니다. 그래야 「스킬 안 쓰는 사람」도
찍을 것이 있습니다.

| 칸 | 무엇 | 왜 이 게임에 필요한가 |
|---|---|---|
| **마나 회수** | 처치 시 마나 +6 | 스킬을 계속 쓰는 리듬(`skills.js` 머리말)의 연료 |
| **랜턴 심지** | 랜턴 연료 소모 −25% | 어둠이 자원인 층(5층)에 대한 답 |
| **죽음의 대가** | 사망 시 장비 손실 없음 (1회, 판당) | 사망 페널티가 있는 게임의 보험 |
| **상성 감각** | 적 이름표에 **약점 속성**이 뜬다 | 4순환 학습을 돕는다. 수치가 아니라 정보 |

## 4. 왜 이 모양인가 — 다른 안을 버린 이유

| 안 | 버린 이유 |
|---|---|
| 디아블로2식 대형 트리 (30~90칸) | 도달 레벨 Lv10~13에서 **4분의 1도 못 찍는다**. 한 판에 다 못 쓰는 시스템은 판 단위 게임에 안 맞는다 |
| 패시브 위주 (「+5% 피해」 다수) | 고민 없이 다 찍는다 = 선택이 아니다 (§1-3) |
| 레벨로 스킬 해금 | 매 판 초반이 벌이 된다 (§1-2) |
| 직업/클래스 분기 | 캐릭터가 하나뿐이라 분기가 곧 재시작이 된다. 트리 안 양자택일이 같은 일을 더 싸게 한다 |
| 무한 성장(파밍 티어와 연동) | 포인트가 계속 쌓이면 결국 전부 찍혀 빌드가 사라진다. **상한이 있어야 선택이다** |

## 5. 화면

### 5-1. 창

`K` 키 (또는 레벨업 토스트 클릭). 인벤토리(`I`)와 같은 창 규격을 씁니다 —
`docs/GUIDE.md`의 조작 규칙을 늘리지 않기 위해서입니다.

```
┌─ 스킬 ────────────────────── 남은 포인트 ◈ 3 ─┐
│                                                │
│  🌀 회전 베기        💨 그림자 돌진             │
│   ●─┬─○                ●─┬─○                  │
│     ├ 연격 ✓             ├ 관통                │
│     └ 가르기 ✗           └ 충격 ✓              │
│   ○ 회오리             ○ 연쇄                  │
│                                                │
│  🔥 화염 신성        ☄ 운석 낙하               │
│   ...                                          │
│                                                │
│  공용   ◆마나 회수 ✓  ◇랜턴 심지  ◇죽음의 대가 │
│                                                │
│  [기억의 재로 되돌리기 — 상점에서 구입]         │
└────────────────────────────────────────────────┘
```

- **찍은 칸**은 색이 차고, **못 찍는 반대편**은 ✗ 로 잠깁니다 (왜 잠겼는지 보여야 합니다)
- 칸에 커서를 올리면 **바뀌는 수치를 지금 값과 나란히** 보여줍니다 —
  상점 줄에 능력치를 붙인 것과 같은 이유입니다

### 5-2. 레벨업 순간

지금은 토스트 한 줄입니다. 포인트가 생기면 **스킬 아이콘 옆에 빨간 점**이 붙고,
그 점이 사라질 때까지 남습니다. 「누를 것이 생겼다」가 안 보이면 시스템이 없는 것과 같습니다.

## 6. 코드에 어떻게 붙는가

### 6-1. 새 파일 하나

```
web/3d/js/game/skilltree.js    // 칸 정의표 + 찍기/되돌리기 + 효과 적용
```

`bossmoves.js`·`floors.js`와 같은 방식입니다 — **표 하나에 다 있고 소비자는 읽기만** 합니다.

```js
export const NODES = {
  cleaveWide: {
    skill: 'cleave', tier: 1, name: '넓은 호', icon: '🌀',
    desc: '부채꼴이 등 뒤 절반까지 넓어진다',
    mod: { spread: 1.15 / 0.78 },          // 곱하는 값만 둔다
  },
  cleaveCombo: {
    skill: 'cleave', tier: 2, name: '연격', excl: 'cleaveRend',   // 양자택일
    ...
  },
};
```

### 6-2. 스킬이 표를 읽게 한다

지금 `skills.js`의 `cast()`는 숫자가 **박혀 있습니다** (`spread = Math.PI * 0.78`).
그걸 한 번 걷어내야 합니다.

```js
// 전
const spread = Math.PI * 0.78, radius = 3.5;
// 후
const m = G.tree.mods('cleave');           // 안 찍었으면 전부 1
const spread = Math.PI * 0.78 * m.spread, radius = 3.5 * m.radius;
```

**값은 하나도 안 바뀝니다** — 안 찍은 상태의 `mods()`가 전부 1을 돌려주므로
지금과 한 글자도 다르지 않아야 합니다. `tools/verify3d.js`의 스킬 검사가
그것을 확인합니다.

### 6-3. 조심할 것

- **`aggregate()`와 겹치지 않게.** 장비 보너스는 `player.recompute()`가 이미
  합산합니다. 트리가 같은 스탯을 또 만지면 두 곳에서 같은 수치가 흘러
  나중에 어느 쪽이 원인인지 못 찾습니다. **트리는 스킬 동작만** 만집니다
- **저장이 없습니다.** 지금 이 게임은 판이 끝나면 전부 사라집니다 —
  트리도 판 단위입니다. 영구 성장은 별개 설계이고 여기서 안 다룹니다
- **RNG를 소비하면 안 됩니다.** 트리 적용이 `rnd`를 부르면 층 지문이 흔들려
  `tools/floor-parity.js` 비교가 무의미해집니다

## 7. 만드는 순서

| 단계 | 하는 일 | 확인 |
|---|---|---|
| **A** | `skilltree.js` 표 + `mods()` + 스킬에서 숫자 걷어내기 | **아무것도 안 찍은 상태가 지금과 완전히 같다** (`verify3d` 스킬 검사 + `boss-moves` 지문) |
| **B** | 포인트 획득 (레벨업·보스·막) + 창 UI | 레벨업 때 빨간 점이 붙는다 |
| **C** | 1단·3단 칸 12개 (양자택일 아님) | 찍으면 화면에서 달라진다 |
| **D** | 2단 양자택일 8개 + 반대편 잠금 | 한쪽을 찍으면 반대편이 ✗ |
| **E** | 공용 4칸 + 「기억의 재」 상점 판매 | 되돌리면 포인트가 전부 돌아온다 |
| **F** | 밸런스 실측 — 빌드별 TTK | 세 빌드의 TTK가 ±25% 안 |

**A가 관문입니다.** 「새 기능이 하나도 안 늘어나는」 작업이라 미루기 쉬운데,
미루면 칸을 하나 만들 때마다 `skills.js`를 헤집게 됩니다
(`docs/FLOORS.md §9`의 A·B와 같은 성격입니다).

## 8. 이 문서가 정하지 않은 것

- **영구 성장** (판을 넘어 남는 것). 지금 게임에 저장이 없습니다
- **정확한 수치.** 위 표의 배율은 **출발점**이지 결론이 아닙니다.
  §7-F에서 재고 나서 고칩니다
- **아이콘·연출.** 칸마다 다른 이펙트를 줄지, 스킬 이펙트만 바뀔지
- **적이 쓰는 트리.** 정예 특성(`elites.js`)이 이미 그 일을 합니다

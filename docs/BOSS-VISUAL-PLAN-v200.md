# 보스 표현 재설계 기획안 (v200~v204)

> 사장 지적: **"왜 바닥에 빨간색 영역만 나오고 동그라미 날리기만 하지?? 처음부터 다시 설계해"**
> 직전 지적: **"상대를 얼리거나 화상을 입히거나 속성도 없고 뭐하는거야?"**
>
> 두 지적은 같은 뿌리다. 이 문서는 패턴을 더 만드는 문서가 **아니다**.
> 이미 있는 패턴이 화면에 어떻게 그려지는가 — **표현 계층**을 처음부터 다시 짜는 문서다.

## 0. 왜 지금까지 안 고쳐졌는가 (자기 진단)

사장은 v187부터 일관되게 같은 말을 했다. "화면에 변화가 안 보인다."
그때마다 내 대응은 전부 **데이터·로직**이었고, **그리는 코드**는 한 번도 건드리지 않았다.

| 회차 | 사장 지적 | 내가 고친 곳 | 화면 |
|---|---|---|---|
| v187 | 군집 체감이 없다 | 군집 생성 로직 | 그대로 |
| v188 | 손맛·회피가 없다 | 예고 시간 숫자 | 그대로 |
| v192~196 | 왜 잡몹만 나와 | `combatComp` (생성기) ×3 | 그대로 |
| v199 | 패턴이 단순하다 | 패턴 풀에 패턴 추가 | 그대로 |
| **지금** | 빨간 영역·동그라미뿐 | — | **원인이 여기** |

**검증 도구가 화면을 보지 않는 것**이 근본 원인이다.
회귀 검사 117개는 전부 상태(state)를 본다. "패턴 5종이 시전됐다"는 검사는
그 5종이 **전부 똑같은 원으로 그려지는 화면에서도 통과**한다.
그래서 매 버전 "검증 통과"로 보고됐고, 화면을 실제로 본 사람은 사장뿐이었다.

→ 이 기획의 **0단계는 도구 수정**이다. 픽셀을 세는 검사가 없으면 이 기획도 같은 길을 간다.

## 1. 계측 — 지금 화면에 무엇이 그려지는가

### 1-1. 보스 공격 표현 인벤토리 (`boss.js` 전수)

|---|---:|---|

| `firePatches` | 7 | 원 (유기적 텍스처 패치) |

### 1-2. 패턴 동사 14개 → 그려지는 도형

```
sweep  fan  ring  charge  mortar  geyser  spiral  beam  pulse  echo  snare  curse  summon  uniq
  호    원    원   붉은띠    원      원      원     원    원    잔상    원     원     원    붉은면
  ✓     ✗    ✗     ✗       ✗      ✗       ✗      ✗     ✗     ✓     ✗     ✗      ✗     ✗
```

**14개 중 12개가 원 또는 단색 붉은 면.**
v199에서 패턴 수를 늘린 것이 체감상 무의미했던 이유가 여기 있다.
**패턴을 늘릴수록 같은 그림이 늘어난다.**

### 1-3. "바닥의 빨간색 영역"의 정체

`render-game.js` 의 `sigs`(왕의 인장기 예고) 렌더 8분기 중 **7분기가 `#e43b44` 단색**:

```
halfSweep · shieldCharge · brandZone · sanctPulse · triCharge · kingCross · miniSig  → 전부 #e43b44
```

예고의 **색이 위험의 종류를 말해주지 않는다.** 전부 같은 빨강이므로
"뭐가 오는지"는 모르고 "위험하다"만 안다. 그래서 대처가 한 가지(도망)뿐이다.

### 1-4. "동그라미 날리기"의 정체

`render-game.js:998` — **모든 적 탄환에 무조건** 붉은 헤일로 원을 덧그린다.

```js
const hr = (style.r || 6) + 5;      // 모양 r≈6 → 헤일로 r≈11
ctx.fillStyle = '#e43b44';
ctx.arc(a.x, a.y, hr + 2, ...); fill();   // 붉은 원 채우기
ctx.arc(a.x, a.y, hr, ...);     stroke(); // 붉은 원 테두리
// ↓ 그 다음에야 뼈/불꽃/파편 모양을 그림
```

v192에 만든 뼈·불꽃·원혼·포자·파편 5종 모양은 **자기보다 2배 큰 붉은 원 안에 잠긴다.**
사장이 "동그라미 날리기"라고 말한 건 정확한 관찰이다. 실제로 화면을 지배하는 건 붉은 원이다.

### 1-4-b. 내가 직접 화면을 보고 확인한 것 (`tools/frame-audit.js`)

사장 질문: *"그래서 직접 못봐서 어떻게 할건데? 스스로 스샷 찍어서 볼거야?"* → **그렇게 했다.**
헤드리스 크로미움으로 1층 보스전을 13초 돌리며 6장을 찍고 내가 직접 봤다.
(`docs/audit/f1-*.png`)

프레임 2 — 사장이 말한 그 화면이 그대로 나온다:
- **뼛조각 탄환 4발이 전부 붉은 원 안에 갇혀 있다.** 뼈 모양은 원 안에서 식별 불가
- 보스 낫질 예고는 **붉은 부채꼴 하나**
- 오른쪽에 **보라 원**(저주 장판) 하나
- 바닥에 흔적 **0**

프레임 4 — 더 심하다:
- **화면에 보이는 위험 표시가 원 5개가 전부다** (보라 원 3겹 + 이중 원 1쌍)
- 팽창 링은 원 두 개일 뿐이라 **"안쪽이 안전"이라는 정보가 화면에 없다**
- 보스가 어디 있는지 한눈에 안 짚인다

자동 집계:

```
── 1층 보스 13초 ──
  도형   circle 38% · bar 32%(HUD) · slab 20%(HUD) · arc 10% · dot 0%
         → 세계에 그려진 것만 보면 circle 79% / arc 21%.  실질 도형 2종
  색상   보라 63% · 주 35% · 적 32% · 자홍 17% · 청록 7%
  바닥   보스 장판 0 · 잔여물 0
  상태   플레이어가 받은 상태이상: 없음
```

**"보스 장판 0 · 잔여물 0 · 상태이상 없음"** — 사장의 두 지적이 같은 숫자로 찍혔다.

### 1-5. 보스는 바닥에 흔적을 안 남긴다

```

```

지속 장판(불바다/빙판/독무)은 **플레이어와 잡몹만** 남긴다.
보스전 3분 동안 방은 처음 모습 그대로다. 싸운 흔적이 없다.

## 2. 재설계 원칙

> **위험의 「모양」이 대처법을 말해야 한다.**
> 원은 "여기 위험"만 말한다. 어디로 피하라는 말을 안 한다.
> 원 하나로 통일된 화면에서는 대처법도 하나뿐이고, 그게 "손맛이 없다"의 실체다.

### 2-1. 도형 문법 5종 — 도형이 곧 대처 동작

| 도형 | 그림 | 위험 | **요구 동작** | 현재 |
|---|---|---|---|---|
| **● 지점** | 원 | 이 자리에 떨어진다 | 옆으로 걸어 나간다 | 40/42 (전부 이것) |
| **▬ 선** | 굵은 띠 + 양끝 화살촉 | 이 선상이 관통된다 | 선에 **수직으로** 대시 | charge만, 단색 붉은 띠 |
| **◤ 부채꼴** | 꼭짓점=보스, 호=사거리 | 이 방향이 쓸린다 | 보스 **뒤로 돌아 들어간다** | 없음 |
| **◎ 고리** | 도넛. **안쪽이 안전** | 바깥이 위험 | 보스에게 **붙는다** | ring은 팽창 원 (안전지대 표시 없음) |
| **▦ 타일** | 바닥 격자가 순서대로 점등 | 밟은 칸이 무너진다 | **정해진 칸으로 이동** | 없음 |

핵심: **◎ 고리는 "보스에게 붙어라"고 명령한다.** 도망만이 정답인 게임에서
"붙어야 산다"가 하나 생기면 그 자체로 긴장의 종류가 늘어난다.
5개 도형 = 5가지 대처 = 5가지 손맛. HP를 올리는 게 아니라 이걸 올린다.

### 2-2. 속성 5종 — 3종 세트가 다 있어야 "속성이 있다"고 읽힌다

속성 하나 = **(탄 색·모양) + (바닥 잔여물) + (플레이어 상태이상)**.
셋 중 하나라도 빠지면 화면에서 속성으로 읽히지 않는다.
현재는 탄 색만 있고 나머지 둘이 **0**이다. 그래서 "속성이 없다"가 맞는 말이다.

| 속성 | 탄 | 바닥 잔여물 | **플레이어 상태이상** | 해제 |
|---|---|---|---|---|
| 🔥 **화상** | 불꽃 · `#ff7043` | 불바다 3.0s | 0.6s마다 1 도트 · 화면 가장자리 붉게 | **계속 움직이면** 빨리 꺼짐 |
| ❄ **빙결** | 파편 · `#8fd3f4` | 빙판 4.0s | **대시 충전 정지** + 이동 −40% | 2.0s 경과 |
| ☠ **중독** | 덩어리 · `#6ab04c` | 독무 4.0s | 회복량 −60% · 약한 도트 | 3.5s 경과 |
| ⚡ **감전** | 섬광 · `#ffd866` | 전류 2.0s | 피격 시 근처 적에게 **연쇄 방전** (플레이어에게 추가타) | 붙어있는 적 제거 |
| 🕯 **저주** | 원혼 · `#b13ae0` | 저주 지대 5.0s | 받는 피해 **+25%** | **보스 부하 처치** |

**❄빙결이 이 설계의 심장이다.** v188에서 세운 회피 자원(대시)을 정면으로 빼앗는다.
"대시가 안 찬다"는 것은 숫자가 아니라 손에서 바로 느껴진다.
그리고 🕯저주는 소환 부하를 처리할 이유를 만든다 — 지금 부하는 무시해도 그만이다.

### 2-3. 헤일로 수술 (v200 즉시)

붉은 헤일로를 **속성색 헤일로**로 바꾸고, **모양보다 작게** 만든다.

```
현재:  붉은 원 r=11  (채우기+테두리) →  그 위에 모양 r=6      = 붉은 원으로 보임
개선:  속성색 글로우 r=6×0.8 (모양 뒤)  →  그 위에 모양 r=7.5   = 모양으로 보임
       위험 식별은 「속성색 + 모양」이 담당. 아이템·보석과는 채도·움직임으로 구분
```

붉은 테두리는 **위험 식별 장치**로 도입된 것이므로 없애지 않는다.
대신 원이 아니라 **모양의 실루엣을 따라가는 얇은 외곽선**으로 바꾼다.
(뼈는 뼈 모양 외곽선, 불꽃은 불꽃 모양 외곽선)

## 4. 구현 순서 — 각 단계가 독립적으로 배포·검증 가능

### 0단계 (v200 선행): **검증 도구가 화면을 보게 한다** ⚠ 최우선

이게 없으면 이 기획은 v199와 같은 길을 간다.

- `tools/frame-audit.js` 신설 — 보스전 13초를 헤드리스로 돌리며 매 프레임 캔버스를 읽어:
  - **화면에 나타난 서로 다른 도형 수** (렌더 호출을 계측 훅으로 태그)
  - **화면에 나타난 서로 다른 색상 수** (지배 색 히스토그램)
  - **보스가 건 상태이상 종류 수**
  - **보스가 남긴 바닥 잔여물 수**
- 회귀 검사에 `visual.*` 계열 추가. **"작동한다"가 아니라 "보인다"를 검사한다.**

### 1단계 (v200): 헤일로 수술 + 예고색 해체

- 탄환 헤일로: 붉은 원 → **속성색 실루엣 외곽선** (§2-3)
- `sigs` 7분기 단색 `#e43b44` → **속성색 + 도형별 표기**로 분리
- **즉시 체감:** "동그라미 날리기"와 "빨간 영역"이 이 단계에서 사라진다

### 2단계 (v201): 플레이어 상태이상 수신 5종 + HUD

- `player.js` 에 `burnT / freezeT / poisonT / shockT / curseT` 신설
- ❄빙결의 **대시 충전 정지** 배선 (v188 회피 자원 축과 직결)
- HUD 상태 아이콘 + 캐릭터 색 오버레이 + 화면 가장자리 색
- 회귀: 각 상태가 **보스에 의해 걸리고** + **화면에 표시되는지** 둘 다 검사

### 3단계 (v202): 보스 바닥 잔여물

- `boss.js` 의 `zones.push` 0회 → 속성별 장판 배선
- 보스가 지나간 자리·착탄 지점에 흔적이 남아 **방이 시간에 따라 변한다**
- 안전지대가 줄어들며 후반부 압박이 생긴다 (HP 인플레 없는 난이도 상승)

### 4단계 (v203): 도형 문법 5종 신설

- ▬선 / ◤부채꼴 / ◎고리 / ▦타일 텔레그래프 렌더러 신설
- 기존 14개 패턴 동사를 5개 도형에 재배치 (§2-1 표)
- 판정과 그림의 폭을 **1:1로 강제** (v175에서 링이 3.3배였던 사고 재발 방지)

### 5단계 (v204): 보스 23종 배정 + 고유 도형

- §3 표 전량 반영
- 보스별 「고유 도형 1개」가 그 보스의 기억점이 된다

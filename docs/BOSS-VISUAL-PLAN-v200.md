# 보스 표현 재설계 기획안 (v200~v204)

> 사장 지적: **"왜 바닥에 빨간색 영역만 나오고 동그라미 날리기만 하지?? 처음부터 다시 설계해"**
> 직전 지적: **"상대를 얼리거나 화상을 입히거나 속성도 없고 뭐하는거야?"**
>
> 두 지적은 같은 뿌리다. 이 문서는 패턴을 더 만드는 문서가 **아니다**.
> 이미 있는 패턴이 화면에 어떻게 그려지는가 — **표현 계층**을 처음부터 다시 짜는 문서다.

## 0. 왜 지금까지 안 고쳐졌는가 (자기 진단)

사장은 v187부터 일관되게 같은 말을 했다. "화면에 변화가 안 보인다."
그때마다 내 대응은 전부 **데이터·로직**이었고, **그리는 코드**는 한 번도 건드리지 않았다.

| 회차 | 사장 지적 | 내가 고친 곳 | 화면 |
|---|---|---|---|
| v187 | 군집 체감이 없다 | 군집 생성 로직 | 그대로 |
| v188 | 손맛·회피가 없다 | 예고 시간 숫자 | 그대로 |
| v192~196 | 왜 잡몹만 나와 | `combatComp` (생성기) ×3 | 그대로 |
| v199 | 패턴이 단순하다 | 패턴 풀에 패턴 추가 | 그대로 |
| **지금** | 빨간 영역·동그라미뿐 | — | **원인이 여기** |

**검증 도구가 화면을 보지 않는 것**이 근본 원인이다.
회귀 검사 117개는 전부 상태(state)를 본다. "패턴 5종이 시전됐다"는 검사는
그 5종이 **전부 똑같은 원으로 그려지는 화면에서도 통과**한다.
그래서 매 버전 "검증 통과"로 보고됐고, 화면을 실제로 본 사람은 사장뿐이었다.

→ 이 기획의 **0단계는 도구 수정**이다. 픽셀을 세는 검사가 없으면 이 기획도 같은 길을 간다.

## 1. 계측 — 지금 화면에 무엇이 그려지는가

### 1-1. 보스 공격 표현 인벤토리 (`boss.js` 전수)

|---|---:|---|
| `curses` (저주 장판) | **22** | **원**. 채우기+테두리. 색만 4가지 |
| `firePatches` | 7 | 원 (유기적 텍스처 패치) |
| `rings` | 6 | 원 (팽창 링) |

### 1-2. 패턴 동사 14개 → 그려지는 도형

```
sweep  fan  ring  charge  mortar  geyser  spiral  beam  pulse  echo  snare  curse  summon  uniq
  호    원    원   붉은띠    원      원      원     원    원    잔상    원     원     원    붉은면
  ✓     ✗    ✗     ✗       ✗      ✗       ✗      ✗     ✗     ✓     ✗     ✗      ✗     ✗
```

**14개 중 12개가 원 또는 단색 붉은 면.**
v199에서 패턴 수를 늘린 것이 체감상 무의미했던 이유가 여기 있다.
**패턴을 늘릴수록 같은 그림이 늘어난다.**

### 1-3. "바닥의 빨간색 영역"의 정체

`render-game.js` 의 `sigs`(왕의 인장기 예고) 렌더 8분기 중 **7분기가 `#e43b44` 단색**:

```
halfSweep · shieldCharge · brandZone · sanctPulse · triCharge · kingCross · miniSig  → 전부 #e43b44
```

예고의 **색이 위험의 종류를 말해주지 않는다.** 전부 같은 빨강이므로
"뭐가 오는지"는 모르고 "위험하다"만 안다. 그래서 대처가 한 가지(도망)뿐이다.

### 1-4. "동그라미 날리기"의 정체

`render-game.js:998` — **모든 적 탄환에 무조건** 붉은 헤일로 원을 덧그린다.

```js
const hr = (style.r || 6) + 5;      // 모양 r≈6 → 헤일로 r≈11
ctx.fillStyle = '#e43b44';
ctx.arc(a.x, a.y, hr + 2, ...); fill();   // 붉은 원 채우기
ctx.arc(a.x, a.y, hr, ...);     stroke(); // 붉은 원 테두리
// ↓ 그 다음에야 뼈/불꽃/파편 모양을 그림
```

v192에 만든 뼈·불꽃·원혼·포자·파편 5종 모양은 **자기보다 2배 큰 붉은 원 안에 잠긴다.**
사장이 "동그라미 날리기"라고 말한 건 정확한 관찰이다. 실제로 화면을 지배하는 건 붉은 원이다.

### 1-4-b. 내가 직접 화면을 보고 확인한 것 (`tools/frame-audit.js`)

사장 질문: *"그래서 직접 못봐서 어떻게 할건데? 스스로 스샷 찍어서 볼거야?"* → **그렇게 했다.**
헤드리스 크로미움으로 1층 보스전을 13초 돌리며 6장을 찍고 내가 직접 봤다.
(`docs/audit/f1-*.png`)

프레임 2 — 사장이 말한 그 화면이 그대로 나온다:
- **뼛조각 탄환 4발이 전부 붉은 원 안에 갇혀 있다.** 뼈 모양은 원 안에서 식별 불가
- 보스 낫질 예고는 **붉은 부채꼴 하나**
- 오른쪽에 **보라 원**(저주 장판) 하나
- 바닥에 흔적 **0**

프레임 4 — 더 심하다:
- **화면에 보이는 위험 표시가 원 5개가 전부다** (보라 원 3겹 + 이중 원 1쌍)
- 팽창 링은 원 두 개일 뿐이라 **"안쪽이 안전"이라는 정보가 화면에 없다**
- 보스가 어디 있는지 한눈에 안 짚인다

자동 집계:

```
── 1층 보스 13초 ──
  도형   circle 38% · bar 32%(HUD) · slab 20%(HUD) · arc 10% · dot 0%
         → 세계에 그려진 것만 보면 circle 79% / arc 21%.  실질 도형 2종
  색상   보라 63% · 주 35% · 적 32% · 자홍 17% · 청록 7%
  바닥   보스 장판 0 · 잔여물 0
  상태   플레이어가 받은 상태이상: 없음
```

**"보스 장판 0 · 잔여물 0 · 상태이상 없음"** — 사장의 두 지적이 같은 숫자로 찍혔다.

### 1-5. 보스는 바닥에 흔적을 안 남긴다

```

```

지속 장판(불바다/빙판/독무)은 **플레이어와 잡몹만** 남긴다.
보스전 3분 동안 방은 처음 모습 그대로다. 싸운 흔적이 없다.

## 2. 재설계 원칙

> **위험의 「모양」이 대처법을 말해야 한다.**
> 원은 "여기 위험"만 말한다. 어디로 피하라는 말을 안 한다.
> 원 하나로 통일된 화면에서는 대처법도 하나뿐이고, 그게 "손맛이 없다"의 실체다.

### 2-1. 도형 문법 5종 — 도형이 곧 대처 동작

| 도형 | 그림 | 위험 | **요구 동작** | 현재 |
|---|---|---|---|---|
| **● 지점** | 원 | 이 자리에 떨어진다 | 옆으로 걸어 나간다 | 40/42 (전부 이것) |
| **▬ 선** | 굵은 띠 + 양끝 화살촉 | 이 선상이 관통된다 | 선에 **수직으로** 대시 | charge만, 단색 붉은 띠 |
| **◤ 부채꼴** | 꼭짓점=보스, 호=사거리 | 이 방향이 쓸린다 | 보스 **뒤로 돌아 들어간다** | 없음 |
| **◎ 고리** | 도넛. **안쪽이 안전** | 바깥이 위험 | 보스에게 **붙는다** | ring은 팽창 원 (안전지대 표시 없음) |
| **▦ 타일** | 바닥 격자가 순서대로 점등 | 밟은 칸이 무너진다 | **정해진 칸으로 이동** | 없음 |

핵심: **◎ 고리는 "보스에게 붙어라"고 명령한다.** 도망만이 정답인 게임에서
"붙어야 산다"가 하나 생기면 그 자체로 긴장의 종류가 늘어난다.
5개 도형 = 5가지 대처 = 5가지 손맛. HP를 올리는 게 아니라 이걸 올린다.

### 2-2. 속성 5종 — 3종 세트가 다 있어야 "속성이 있다"고 읽힌다

속성 하나 = **(탄 색·모양) + (바닥 잔여물) + (플레이어 상태이상)**.
셋 중 하나라도 빠지면 화면에서 속성으로 읽히지 않는다.
현재는 탄 색만 있고 나머지 둘이 **0**이다. 그래서 "속성이 없다"가 맞는 말이다.

| 속성 | 탄 | 바닥 잔여물 | **플레이어 상태이상** | 해제 |
|---|---|---|---|---|
| 🔥 **화상** | 불꽃 · `#ff7043` | 불바다 3.0s | 0.6s마다 1 도트 · 화면 가장자리 붉게 | **계속 움직이면** 빨리 꺼짐 |
| ❄ **빙결** | 파편 · `#8fd3f4` | 빙판 4.0s | **대시 충전 정지** + 이동 −40% | 2.0s 경과 |
| ☠ **중독** | 덩어리 · `#6ab04c` | 독무 4.0s | 회복량 −60% · 약한 도트 | 3.5s 경과 |
| ⚡ **감전** | 섬광 · `#ffd866` | 전류 2.0s | 피격 시 근처 적에게 **연쇄 방전** (플레이어에게 추가타) | 붙어있는 적 제거 |
| 🕯 **저주** | 원혼 · `#b13ae0` | 저주 지대 5.0s | 받는 피해 **+25%** | **보스 부하 처치** |

**❄빙결이 이 설계의 심장이다.** v188에서 세운 회피 자원(대시)을 정면으로 빼앗는다.
"대시가 안 찬다"는 것은 숫자가 아니라 손에서 바로 느껴진다.
그리고 🕯저주는 소환 부하를 처리할 이유를 만든다 — 지금 부하는 무시해도 그만이다.

### 2-3. 헤일로 수술 (v200 즉시)

붉은 헤일로를 **속성색 헤일로**로 바꾸고, **모양보다 작게** 만든다.

```
현재:  붉은 원 r=11  (채우기+테두리) →  그 위에 모양 r=6      = 붉은 원으로 보임
개선:  속성색 글로우 r=6×0.8 (모양 뒤)  →  그 위에 모양 r=7.5   = 모양으로 보임
       위험 식별은 「속성색 + 모양」이 담당. 아이템·보석과는 채도·움직임으로 구분
```

붉은 테두리는 **위험 식별 장치**로 도입된 것이므로 없애지 않는다.
대신 원이 아니라 **모양의 실루엣을 따라가는 얇은 외곽선**으로 바꾼다.
(뼈는 뼈 모양 외곽선, 불꽃은 불꽃 모양 외곽선)

### 2-4. 반응 규칙 — 6번째 축 (사장 승인, 신규)

> 사장: **"보스가 많잔아? 그걸로 충분해? 재미를 위해서?"**

계측 답: **아니다. 그리고 지금은 많은 것이 해가 되고 있다.**

```
23종  →  기믹 5종  →  패턴 동사 14종  →  화면 도형 2종      ← 바닥에서 짓눌린다

보스 쌍 253개의 평균 패턴 유사도   0.46      아무 둘을 골라도 패턴 절반을 공유
유사도 0.6 이상                   52쌍 (21%)
완전 동일(1.00)                   1쌍 — 사슬에 얽힌 바르곤 ≡ 수문장 '갈고리 브람'
0.89 무거운 손↔이노첸시오 · 0.86 몰레↔코르부스 · 0.86 물에 불은 몰레↔로트가르
```

그리고 결정적으로 — **사장 최근 런은 2층·3층·3층.**
23종 중 실제로 만나는 건 2~3종이고, **나머지 20종(87%)은 사장 게임에 존재하지 않는다.**

Hades 보스 4마리, Dead Cells 5마리. 이 장르의 재미는 *처음 보는 보스 23마리*가 아니라
**같은 보스를 20번 만나 결국 이기게 되는 과정**에서 나온다.
23종에 노력을 나눠 담다 보니 공용 동사 14개를 재조합하게 됐고 → 유사도 0.46 →
렌더가 그걸 도형 2개로 뭉갰다. **넓혀서 얕아진 것.**

#### 빠져 있던 축: 보스가 플레이어에게 반응하지 않는다

```
boss.js 반응 트리거 전수 (23종 공통)
  d > 300  → 원거리 패턴 선호     (v199에서 추가)
  d < 150  → 근접 패턴 선호
  ───────────────────────────────
  대시를 써도 · 회복해도 · 가만히 서 있어도 · 딜을 쏟아부어도   → 반응 없음
```

**내가 무슨 짓을 해도 보스가 모른다.** "내가 뭔가 했다는 생각이 안 든다"의 나머지 절반이 여기다.
도형과 속성을 고쳐도 이게 없으면 화려한 자동재생일 뿐이다.

**설계:** 각 보스는 **확정 규칙 1~2개**를 가진다. 확률이 아니라 규칙이어야 해독되고,
해독돼야 숙달된다. 규칙은 예고 배너에 **한 줄로 표시**해 플레이어가 읽을 수 있게 한다.

| 보스가 읽는 것 | 규칙 예 |
|---|---|
| **대시 사용** | 오스문드 — 낫질을 대시로 3연속 회피하면 「낫을 고쳐쥔다」 → 즉시 2연속 낫질(대시 쿨 안에 두 번). **해법: 대시를 아끼고 걸어서 뒤로 돌아간다** |
| **회복·물약** | 몰레 — 플레이어가 회복하면 다음 패턴이 반드시 ☠중독 (회복량 −60%). **해법: 안전 구간에서만 마신다** |
| **정지 시간** | 바르곤 — 1.5초 이상 안 움직이면 발밑 ❄빙판. **해법: 계속 움직인다** |
| **딜 집중** | 브란트 — 짧은 시간에 큰 피해를 받으면 즉시 🔥자기 주변 폭발. **해법: 딜을 끊어 넣는다** |
| **거리 유지** | (이미 있음) 멀면 원거리 / 붙으면 근접 |

플레이어가 배우는 것은 숫자가 아니라 **"이 보스에게는 대시가 자원이다"** 같은 문장이다.
그게 손맛이고, 그게 20번 만나도 재밌는 이유다.

### 2-5. 아트 — 보스가 뭘 들고 있는지 구분되게 (사장 지적, 신규)

> 사장: **"디자인 퀄러티가 너무 떨어지는데 어떻게 할지 말해줘"**
> **"보스가 뭘 들고 있는지도 구분이 안되잔아"**

`tools/sprite-sheet.js` 로 23종을 8배 확대해 직접 봤다. 원인 6가지:

| # | 문제 | 계측 |
|---|---|---|
| ① | **원본이 너무 작다** | 보스 원본 28~34px을 화면 86~120px로 뿌린다. 배율 2.7~4.0배 — **한 픽셀이 화면 3px 블록**이라 무기처럼 작은 것은 뭉갠다 |
| ② | **무기가 무기 모양이 아니다** | 오스문드의 '낫'은 굽어 있지 않다. 막대 끝에 붙은 4×5px 사각형 |
| ③ | **손이 없다** | 무기가 몸에서 1px 떨어져 공중에 떠 있다. 들고 있다고 안 읽힌다 |
| ④ | **무기 실루엣이 중복** | 오스문드·몰레·로트가르·무거운 손·갈고리 브람 5명이 "세로 막대 + 작은 사각 날"로 동일 |
| ⑤ | **무기가 판독 불가** | 퀼른·흰 늑대·이노첸시오·무언의 기수는 무기가 **흰색 세로 직사각형 하나**. 검인지 지팡이인지 알 수 없다 |
| ⑥ | **몸 실루엣이 전부 같다** | 23종 중 20종이 "둥근 머리 + 사각 몸통 + 두 다리" |

#### 해법 — 원본 해상도를 올리고, 무기를 별도 레이어로 뽑는다

**(가) 보스 원본 48×48** — 화면 크기는 그대로 두고 배율을 1.8배로 낮춘다.
같은 86px인데 **디테일이 2.25배**. 스프라이트는 코드로 그리므로 외부 에셋이 필요 없다.

**시제품 실측** (`tools/sprite-proto.js` → `docs/audit/proto-osmund.png`):

```
        원본        화면      낫 날 픽셀        손
  A 현재  32×29px    86px     20px (사각형)     없음 — 무기가 몸에서 떠 있다
  B 시제품 48×48px    86px    109px (초승달 호)  자루를 쥔 손 있음
```

B는 챙 넓은 모자 · 초승달 낫 · 등불 · 쥔 손이 **게임 안 실제 크기(86px)에서 구분된다.**

**(나) 무기를 스프라이트에서 분리해 별도 레이어로** — 이게 §2-1(도형)과 직결된다.
지금은 낫질 예고가 붉은 부채꼴인데 **낫은 가만히 있다.** 무기를 분리하면:
- 휘두를 때 실제로 휘둘러진다 (◤부채꼴 예고와 무기 궤적이 일치)
- 무기가 커질 수 있다 (몸 밖으로 나가도 됨)
- 속성색 발광을 무기에만 입힐 수 있다 (🔥브란트의 창은 주황으로 달아오른다)

**(다) 실루엣 차별화 3계층** — 멀리서 봐도 누군지 알아야 한다.
`머리 형태`(챙모자 / 투구 / 두건 / 가면 / 왕관) × `몸 비율`(장신 / 육중 / 왜소) ×
`무기 실루엣`(낫 / 도끼 / 대검 / 창 / 지팡이 / 철퇴 / 갈고리 / 방패).
1~5층 5종은 **셋 다 서로 다르게** 확정한다.

## 3. 범위 — 1~5층 5종에 전량 투입 (사장 승인)

**보스 수를 늘리지 않는다.** 23종은 그대로 두되, 설계 노력은 1~5층에 몰아넣는다.
1층 오스문드 하나가 **20번 만나도 재밌어지면** 나머지 18종은 그 문법을 갈아 끼우는 작업이 된다.
반대로 이게 안 되면 46종을 만들어도 똑같다. (v198에서 1~5층을 이미 규격으로 정한 것과도 맞물린다)

| 층 | 보스 | 속성(주/부) | 고유 도형 | 반응 규칙 | 실루엣 (머리 / 몸 / 무기) |
|---:|---|---|---|---|---|
| 1 | 무덤지기 오스문드 | 🕯 저주 | **◤ 부채꼴** | 대시 3연속 회피 → 2연속 낫질 | 챙 넓은 모자 / 보통 / **낫** |
| 2 | 시체 짐꾼 '삯꾼 몰레' | ☠ 중독 | **● 지점 연쇄** | 회복하면 다음은 반드시 중독 | 두건 / 육중 / **갈고리** |
| 3 | 간수장 바르곤 | ❄ 빙결 / 🕯 저주 | **▬ 선** | 1.5s 정지 → 발밑 빙판 | 투구 / 육중 / **방패+철퇴** |
| 4 | 방화대장 '그을음 브란트' | 🔥 화상 | **▦ 타일** | 딜 집중 → 즉시 자기 주변 폭발 | 가면 / 장신 / **불붙은 창** |
| 5 | 교수대의 그림자 | 🕯 저주 / ❄ 빙결 | **◎ 고리** | 부하 살아있으면 저주 안 풀림 | 없음(그림자) / 왜소 / **올가미** |

5층까지 **도형 5종·속성 4종·반응 5종·무기 실루엣 5종이 전부 한 번씩** 나온다.
6층 이후 18종은 이 5개의 조합을 갈아 끼운다 (§2-4 유사도 0.46 문제도 여기서 풀린다).

### 바닥 잔여물 — 계측이 0이던 곳

`boss.js` 의 `zones.push` 는 **0회**였다. 보스전 3분 동안 방이 처음 모습 그대로였다.
이제 보스의 저주 장판이 터질 때마다 속성 잔여물이 남는다.

★ **1차 배선의 실패**: 잔여물을 「맞았을 때만」 남기게 했더니 계측에서 1·2·4층이 전부 0이었다.
빗나가도 바닥은 그을려야 한다 — **잔여물을 명중과 분리**했다. 그게 「방이 시간에 따라 변한다」는 뜻이고,
HP 인플레 없이 후반 압박을 만드는 장치다.

★ **소환과 저주를 한 쌍으로**: 소환은 크게 예고되는 순간이라 여기서 속성을 건다.

# 새 프로젝트가 이 저장소에서 가져가는 것

`spacewar` 처럼 **다음 게임을 새 저장소에서 시작할 때** 무엇을 들고 가고
무엇을 두고 가는지 적어 둔 문서입니다.

## 0. 왜 이 문서가 필요한가

새 판을 시작하면 두 가지 중 하나를 합니다. **전부 복사하거나, 전부 처음부터.**
둘 다 틀립니다.

- 전부 복사하면 **던전 크롤러의 전제가 따라옵니다.** 층·회차·랜턴·영혼 조각은
  이 게임의 세계관이지 다음 게임의 것이 아닙니다. 그걸 안 지우면 우주선에
  「층」이 생깁니다
- 전부 처음부터 하면 **다섯 번 태운 것을 또 태웁니다.** `docs/POSTMORTEM.md`
  의 일곱 가지 실수는 게임 장르와 아무 상관이 없습니다 — 그림을 코드로
  만들다가 날린 닷새, 캐시버스트가 어긋나 「체감이 없다」던 스무 번의 배포는
  우주 슈팅에서도 똑같이 일어납니다

그래서 **줄 단위로 갈라 둡니다.** 이 문서가 그 선입니다.

## 1. 참조하는 방법

이 저장소는 **공개**입니다 (`github.com/tepalmafia/DungeonCrawler`).
새 저장소에서 아무 제약 없이 읽습니다. 세 가지 중에 고릅니다.

| 방법 | 언제 | 명령 |
|---|---|---|
| **그냥 읽기** | 대부분 — 「저기선 어떻게 했더라」 | 위 주소를 열거나 `git clone` 후 옆에 둔다 |
| **뼈대 복사** | 새 저장소를 처음 세울 때 (권장) | `node tools/export-starter.js ../spacewar` |
| 서브모듈 | 권장하지 않음 | — |

**서브모듈을 권하지 않는 이유:** 가져갈 것이 «같이 굴러가야 할 라이브러리»가
아니라 «한 번 베끼고 각자 갈라질 뼈대»입니다. 서브모듈로 묶으면 다음 게임의
필요 때문에 이 게임의 표를 고치게 되고, 그 순간 **여기 밸런스가 저기 사정으로
움직입니다.** 복사해서 갈라지는 편이 낫습니다.

## 2. 그대로 가져가는 것 — 손 안 대도 되는 것

여기 있는 것은 **게임 장르와 무관하게 맞았던 것**들입니다.

| 파일 | 무엇 | 왜 그대로인가 |
|---|---|---|
| `docs/POSTMORTEM.md` | 일곱 가지 실수 | 그래픽·에셋·확인 방법의 실패다. 장르와 무관하다 |
| `web/3d/js/core/rng.js` | 시드 RNG (mulberry32) | 40줄, 의존성 0. `?seed=ABC123` 규약까지 그대로 쓴다 |
| `tools/serve.py` | 로컬 정적 서버 + 에셋 목록 자동 생성 | 경로 두 줄만 바꾸면 된다 |
| `tools/bump-version.js` | `VERSION` ↔ `?v=` 동기화 | v187~v189 사고를 막은 도구. 정적 배포면 어디서나 필요하다 |
| `tools/assets.js` | 배포용 에셋 목록 생성 | 규격표를 정규식으로 읽는 구조가 그대로 통한다 |

`web/3d/js/core/metrics.js` 는 **반쯤** 그대로입니다. 「매 프레임 경로에서
할당하지 않는다 · 원본 표본을 버리지 않는다 · 표본 수에 상한을 둔다 ·
측정이 게임을 바꾸지 않는다」 네 원칙과 `stats()` 는 그대로 쓰고,
`ttk` · `fights` 같은 **필드 이름만 새 게임의 것으로 갈아 끼웁니다.**

## 3. 구조만 가져가는 것 — 내용은 새로 쓴다

여기가 이 저장소에서 제일 값이 나가는 부분입니다. **파일을 베끼는 게 아니라
배치를 베낍니다.**

### 3-1. 숫자는 표 한 곳에, 게임과 시뮬이 같은 표를 읽는다

`CLAUDE.md` 의 「숫자는 한 곳에만 둡니다」가 이것입니다. 지금 이 저장소에서는
여섯 개의 표가 그 역할을 합니다:

```
game/item-table.js  game/enemy-table.js  game/growth-table.js
game/economy-table.js  game/skill-table.js  world/floors.js
```

**이 표들은 three.js 를 안 씁니다.** 그래야 브라우저 없이 `node` 가 읽습니다.
`tools/sim.js` 와 `tools/tiers.js` 가 게임과 **똑같은 표를 import** 해서
1초 만에 밸런스를 찍습니다 — 시뮬에 숫자를 손으로 옮겨 적지 않기 때문에
표를 고치면 답도 같이 바뀝니다.

새 게임에서 표의 **이름**은 달라집니다 (`ship-table.js` · `weapon-table.js` ·
`wave-table.js` …). 지켜야 할 것은 이름이 아니라 셋입니다:

1. 밸런스 숫자는 표 밖에 안 적는다
2. 표는 렌더러(three.js 등)를 import 하지 않는다
3. 시뮬은 그 표를 **읽는다.** 베껴 적지 않는다

### 3-2. 목적을 숫자로 못박고, 바꿀 때마다 잰다

`CLAUDE.md` 의 목표표(한 마리 잡는 시간 1.5~3초, 회차 하나 15~25분 …)와
`tools/sim.js` 가 찍는 ✔/✘ 가 한 쌍입니다. **감상을 잴 수 있는 형태로
바꿔 놓은 것**이 요점이고, 새 게임에서는 그 지표가 완전히 달라집니다
(우주 슈팅이면 「한 웨이브 길이」·「탄막 밀도」·「무피격 구간」쯤).

만들 때 실제로 도움이 된 습관 하나: **목표끼리 안 맞으면 그때 드러납니다.**
층 목표 3~5분과 회차 목표 15~25분이 서로 안 맞아서(3분 × 6층 = 18분이라
회차 아래 절반이 안 닿음) 층 쪽을 2.5~4분으로 고쳤습니다. 숫자로 안 적어
뒀으면 영영 몰랐을 종류의 어긋남입니다.

### 3-3. 에셋 통로를 게임 로직보다 **먼저** 뚫는다

`docs/POSTMORTEM.md §2` 의 0단계입니다. 이 저장소에서의 모양은:

```
docs/ART-REQUEST.md          사람이 읽는 규격
core/asset-table.js          기계가 읽는 규격  ← 규격은 여기 한 번만 적는다
core/assets.js               로더 (이름 틀리면 콘솔이 그 자리에서 말한다)
tools/serve.py               로컬: 요청마다 폴더를 훑어 목록을 만든다
tools/assets.js --write      배포: 목록을 파일로 굳힌다
web/3d/assets/               ★ 여기 떨어뜨리면 게임에 나온다
```

**규격을 문서와 코드에 두 번 적으면 안 됩니다.** 요구서엔 512×870 이라 써 놓고
코드는 정사각형을 기대하는 상태가 제일 위험합니다 — 파일을 넣어도 아무 일이
안 일어나고 **오류도 안 납니다.**

### 3-4. 낡은 저장은 살리지 말고 버린다

`game/save.js` 의 규약입니다. 저장에 판본을 붙이고, 안 맞거나 읽다 예외가 나면
**말없이 버립니다.** 저장을 살리려다 게임을 못 켜는 쪽이 훨씬 나쁩니다.

같이 따라오는 규칙: **저장에 표의 복사본을 굳히지 않습니다.** 랜턴을 `def`
참조째로 JSON 에 굳혔더니 표를 고쳐도 옛 저장만 옛 값으로 돌았습니다 —
key 만 저장하고 불러올 때 지금 표에서 다시 찾습니다.

### 3-5. 전체 템포를 한 상수로 묶는다

`game/pace.js` 입니다. 개별 수치는 「서로의 차이」를, `MOVE_SCALE` ·
`ATTACK_SCALE` 같은 상수는 「전체 템포」를 담당합니다. 둘을 섞으면 조정할 때마다
스무 곳을 만지고 반드시 하나를 빠뜨립니다.

**함정 하나가 여기 있습니다.** 시간으로 적힌 값(선딜·후딜·쿨다운)은 속도의
**역수**를 곱해야 합니다. 속도 0.7배 = 걸리는 시간 1/0.7 ≈ 1.43배. 여기서
헷갈리면 예고 링과 실제 타격 시점이 어긋나 「예고 없이 맞는」 최악의 버그가
됩니다.

### 3-6. 소리는 없어도 돌아가게

`core/samples.js` 입니다. 녹음 파일이 **하나도 없어도 게임이 똑같이 돌고**,
파일을 넣으면 그때부터 샘플이 납니다. 「나중에 붙이겠다」로 미루면 그 사이
합성 쪽에 다시 손대게 되고, 파일이 들어온 날 두 벌을 합치는 일이 생깁니다.

## 4. 가져가면 안 되는 것

| 안 가져가는 것 | 이유 |
|---|---|
| `core/models.js` 의 다섯 몸 | **주신 그림이 올 때까지의 임시**다. 새 판에 옮기면 임시가 영구가 된다 |
| `world/floors.js` · `game/lantern.js` · 영혼 조각 | 던전 크롤러의 세계관이다. 우주선에 「층」을 만들지 않는다 |
| `docs/` 의 기획 문서 9개 | FLOORS · ELEMENTS · SKILL-TREE · STORY 전부 이 게임 것이다 |
| `web/3d/vendor/three` | 새 저장소에서 필요한 버전을 새로 받는다 |
| 폴더 이름의 `/3d` | 옛 2D 게임과 나란히 두느라 생긴 이름이다. 새 저장소는 `web/` 하나면 된다 |
| 옛 목적의 흔적 | 「드랍 빈도는 줄인다」·「한 마리씩 끌어와 오래 싸운다」는 **뒤집힌 목적**이다 (`docs/GRIND.md §7`). 주석에 아직 남아 있으니 베낄 때 걸러낸다 |

## 5. 뼈대 뽑기 — 한 줄

```
node tools/export-starter.js ../spacewar
node tools/export-starter.js ../spacewar --name spacewar --title "스페이스워"
```

§2 의 「그대로 가져가는 것」을 새 저장소 구조(`web/` 평평하게)로 복사하고,
`CLAUDE.md` · `README.md` 를 이 문서를 가리키는 상태로 만들어 둡니다.
**이미 있는 파일은 덮어쓰지 않습니다** (`--force` 로만 덮습니다).

뽑아내는 것은 **뼈대뿐입니다.** §3 의 표·시뮬·목표 숫자는 새 게임의 것이라
빈 자리로 남고, 그 자리를 채우는 게 새 저장소의 첫 작업입니다.

## 6. 새 저장소에서 제일 먼저 할 일 — 순서

`docs/POSTMORTEM.md §2` 의 순서를 새 판에 맞춘 것입니다.

1. **`CLAUDE.md` 의 「목적 — 한 줄」을 채운다.** 이게 없으면 나머지 판단이 전부
   근거를 잃는다
2. **목표를 숫자로 적는다.** 아직 못 잰다 해도 적어 둔다 — 못 재는 것과
   안 정한 것은 다르다
3. **에셋 통로를 뚫는다.** 게임 로직보다 먼저. 규격표 한 장 + 로더 +
   `assets/` 에 파일 떨어뜨리면 화면에 나오는 상태
4. **세로로 한 줄을 끝낸다.** 「띄우고 → 움직이고 → 부딪히고 → 죽는다」가
   한 번 끝까지 도는 것. 폭은 그다음이다
5. **표와 시뮬을 세운다.** 숫자가 흩어지기 전에. 흩어진 뒤에 모으는 건
   몇 배로 든다
6. 그다음부터 **화면 면적 순으로.** 배경·조명이 98%, 캐릭터가 2%다

---

이 문서에서 확인 안 된 것: §5 의 도구는 `spacewar` 저장소가 아직 없는 상태에서
빈 폴더를 대상으로만 돌려 봤습니다. 실제 새 저장소에 뽑아 넣고 서버를 띄워
본 것은 아닙니다.

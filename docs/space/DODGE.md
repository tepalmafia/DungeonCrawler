# 회피 — 경고 · 방향 · 창 (기획)

> 사장님 (2026-08-13)
> 「적이 미사일을 발사하고 내 화면에 **경고창**이 뜨면서 **특정 방향으로 틀라는
> 네비게이션**이 나오고 **그거대로 누르면 완벽 회피**할 수 있도록 해줘.
> **특정 타이밍 안에 늦거나 못 누르면 피해도가 커지도록** 하고.
> 기존에 겹치는 부분이 있으면 없애고, 블록아웃으로 테스트하고 구현해. 기획부터」

**이 문서는 손으로 적습니다.** 숫자는 `game/dodge-table.js` 가 갖고,
`tools/space-dodge.js` 가 지킵니다 — 여기 적힌 값과 표가 갈라지면 표가 맞습니다.

---

## 0. 기획하기 전에 **쟀습니다**

이 저장소의 규약대로 (`docs/PLANNING.md` — 「기획은 재는 것에서 시작한다」)
쓰기 전에 지금 있는 것을 셌습니다. **다섯 중 셋이 이미 있었습니다.**

| 사장님이 시키신 것 | 지금 | 어디 |
|---|---|---|
| 적이 미사일을 쏜다 | **있다** | `target-table.js ENEMY_FIRE` (3.4초마다 · 105m · 0.9초 비행) |
| 경고가 뜬다 | **있다** | `AI_LINES.evade` · 줄어드는 고리 (`evade-table.js ringAt`) |
| 어느 쪽으로 틀지 말한다 | **있다** | `evadeDir()` → 「좌현으로 · 우현으로 · 기수를 올려 · 기수를 내려」 |
| 그대로 하면 **완벽 회피** | **없다** | ↓ §1 |
| 늦거나 못 누르면 **피해가 커진다** | **없다** | ↓ §2 |

## 1. ★★★ 제일 큰 것 — **말은 방향을 하는데, 판정은 방향을 안 본다**

```js
// target-table.js — 지금
export function evadeGain(relAz, relEl, sx, sy) {
  …
  return Math.abs((relAz / m) * sy - (relEl / m) * sx);   // ← Math.abs
}
// target.js — 지금
roll: Math.abs(evade.roll ?? 0),                          // ← 또 Math.abs
```

**부호를 버립니다.** 그래서 화면이 「좌현으로 빼십시오」라고 말한 다음,
사람이 **오른쪽으로 밀어도 점수가 똑같습니다.** 굴리기도 Q 든 E 든 같습니다.

> ★★★ 이건 이 저장소가 이름까지 붙여 둔 병입니다 — **「재는 곳을 둘로
> 만들지 않는다」.** 가리키는 자리(`evadeDir`)와 매기는 자리(`evadeGain`)가
> 갈라져 있었고, 갈라진 채로 **v84 부터 열두 판**을 왔습니다.
> 그래서 사장님께 「그거대로 누르면 완벽 회피」가 **안 됐던** 것이지,
> 안내가 없어서가 아닙니다.

## 2. 둘째 — **늦어도 안 아픕니다**

```js
export const hurtMult = (got) => …1 - EVADE.soften * min(1, got / NEED);
```

피해는 **쌓은 양**에만 반비례합니다. **늦었다는 것 자체는 값이 없습니다.**
사장님은 「늦거나 못 누르면 피해도가 **커지도록**」이라고 하셨습니다 —
지금은 늦으면 **원래 피해**일 뿐, 더 아프지 않습니다.

## 3. 셋째 — **「완벽」이라는 상태가 없습니다**

지금은 쌓은 양이 `DODGE.need`(1.0)를 **넘느냐 마느냐**뿐입니다. 그리고
v84 가 저울을 이렇게 잡아 뒀습니다:

```
아무것도 안 함      0      → 맞는다
조종간만 끝까지     0.9    → 모자란다        ← **급기동 없이는 못 피한다**
급기동 + 조종간     3.06   → 피한다
```

즉 **추진제를 태우지 않으면 완벽 회피가 원천적으로 불가능**했습니다.
사장님의 새 말씀(「그거대로 누르면 완벽 회피」)은 **이 저울을 뒤집습니다.**

> ★★ **뒤집힌 것을 적어 둡니다** (`WAR.md §9` · `PLAN2H §8` 과 같은 규약).
> 「조종간만으로는 못 피한다 — 급기동을 써야 하고 급기동은 추진제를
> 태운다」(v84)는 **이제 낡은 것**입니다. 급기동은 **여전히 값이 있지만**
> (창을 넓힙니다 · §6), **없어도 맞추면 완벽히 피해집니다.**

## 4. 없앨 겹침 — **누적 모형을 접습니다**

지금 회피 판정에 값을 넣는 자리가 **다섯**입니다:

```
flyPush.yaw/pitch → evadeGain → push ┐
flyPush.roll                  → roll ├→ gainAt(창 배수 · 완벽 배수 · 급기동 배수)
burstNow(급기동)              → mult ┘        → s.dodge 누적 → need 와 견줌
```

**다섯 군데가 곱해져 하나의 숫자가 됩니다.** 그래서 어느 하나를 만지면
나머지 넷이 같이 움직이고, 실제로 v111 이 「2.2/4.0 은 너무 후하다」로
한 번 되돌렸습니다. 그리고 **이 숫자에는 방향이 없습니다** (§1).

★★★ **접습니다.** 회피는 이제 **누적**이 아니라 **한 번의 판정**입니다:

```
   경고가 뜬다 ──▶ 방향 하나를 말한다 ──▶ 창 안에 그 키를 누른다
                                          ├ 맞다 + 제때  → 완벽 (피해 0)
                                          ├ 맞다 + 늦다  → 피해 ×(늦은 만큼)
                                          ├ 틀리다       → 피해 그대로
                                          └ 안 누른다    → 피해 ×최대
```

**남기는 것 · 접는 것**

| | 무엇 | 왜 |
|---|---|---|
| 남긴다 | `ENEMY_FIRE` · `evadeDir` · 고리(`ringAt`) · 슬로우 · RWR | 이미 맞게 돌고 있다 |
| 접는다 | `EVADE.mult` · `perfectMult` · `roll` · `rollOutside` · `soften` | 누적 모형의 부품이다 |
| 접는다 | `evadeGain` 의 `Math.abs` | **방향을 버리던 그 줄**이다 |
| 접는다 | `DODGE.need` 로 견주는 판정 | 「얼마나 쌓았나」가 아니라 「맞췄나」다 |

> ★ **지우지는 않습니다.** `space-reach.js`·접힌 검사 아홉과 같은 규약으로,
> 표에 남기되 **아무도 안 읽는 상태**로 두고 왜 접었는지를 적습니다.

## 5. 방향 넷 — **어느 키를 누르나**

`evadeDir` 은 이미 네 마디를 말합니다 (좌현 · 우현 · 기수 올려 · 기수 내려).
**키를 새로 안 만듭니다** — 이미 손에 있는 것으로 넷을 만듭니다:

| 말 | 키 | 지금 그 키가 하는 일 | 겹치나 |
|---|---|---|---|
| **좌현으로 뺀다** | `A` | 요 왼쪽 | 안 겹친다 — 같은 동작이다 |
| **우현으로 뺀다** | `D` | 요 오른쪽 | 〃 |
| **좌로 굴려 뺀다** | `Q` | 롤 왼쪽 | 〃 (v111 이 회피로 쓰던 키다) |
| **우로 굴려 뺀다** | `E` | 롤 오른쪽 | 〃 |

★★ **왜 굴리기가 위아래를 대신하나.** 피치는 이 게임에서 **마우스**이고
키가 없습니다. 키를 새로 만들면 손 배치(`keys-table.js`)가 늘고, 이 저장소는
「일곱을 넘기지 않는다」를 지켜 왔습니다. 그리고 **실기의 브레이크는 굴려서
당기는 것**이므로, 위아래로 오는 탄에 「굴려서 뺀다」는 말이 됩니다.

★ **마우스로도 됩니다.** 조종간을 그 쪽으로 밀고 있으면 키와 같이 칩니다 —
「들어가는 길을 하나만 만들지 않는다」.

## 6. 숫자 — **표가 갖고, 도구가 지킵니다**

탄이 나는 시간은 **0.9초**(`ENEMY_FIRE.fly`)로 그대로 둡니다.

| | 값 | 왜 |
|---|---|---|
| 경고가 뜨는 때 | 남은 **0.9초** (쏘자마자) | 반응 시간(0.20~0.25초)의 세 배는 줘야 「보고 누른다」가 된다 |
| **완벽** 창 | 남은 **0.55 ~ 0.15초** | 0.4초짜리. 반응 시간의 **약 두 배** — 보고 누를 수 있다 |
| **늦음** 창 | 남은 **0.15 ~ 0초** | 눌리기는 하는데 아프다 |
| 완벽하면 | 피해 **×0** | 사장님 「완벽 회피」 |
| 늦으면 | 피해 **×1.0 → ×1.6** (늦을수록) | 「늦으면 피해도가 커진다」 |
| 틀린 방향 | 피해 **×1.3** | 반대로 꺾으면 **탄 쪽으로** 가는 것이다 |
| 안 누름 | 피해 **×1.8** | 제일 아프다 — 그래야 경고를 본다 |
| 급기동(Shift) | 완벽 창을 **±0.08초** 넓힌다 | v84 의 급기동을 **안 죽인다** — 상이 「피한다」에서 「쉬워진다」로 바뀐다 |

★ **「반사」 특성**(`growth-table.js`)은 그대로 창을 넓힙니다 — 사람이 크는
자리를 안 없앱니다.

## 7. 블록아웃 — **이 순서로 만듭니다** (예외 없음)

```
① game/dodge-table.js     three 를 안 쓴다. 「경고 → 방향 → 판정」만
② tools/space-dodge.js    게임을 안 부른다. 아래 일곱을 묻는다
③ 게임에 물린다           target.js 가 **묻기만** 한다 (제 셈을 안 한다)
④ 화면과 대조             space-endtoend.js 에 한 절 — 진짜 키로
```

**도구가 묻는 일곱**

1. **넷이 다 나오나** — 오는 방위를 훑어 네 방향이 다 지시되나
2. **맞게 누르면 완벽인가** — 창 안 + 맞는 키 → 피해 0
3. ★★★ **틀리게 누르면 손해인가** — 반대 키가 「안 누른 것」보다 낫지 않나
4. **늦으면 커지나** — 늦을수록 단조 증가인가
5. **안 누르면 제일 아픈가**
6. ★★ **아무 키나 다 누르는 것이 답이 아닌가** — 넷을 다 눌러도 안 통하나
7. ★★ **눈 감고 찍으면 얼마나 되나** — 25% 근처인가 (넷 중 하나)

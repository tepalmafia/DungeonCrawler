## 1. 실제 조종석은 얼마나 보나 — **찾아본 것**

| 기준 | 아래로(over-the-nose) | 세로 전체 |
|---|---|---|
| **FAA AC 25.773-1** (여객기 시야 설계) | **17°** | 정상 시선을 수평 아래 15°에 두고 ±15° 가 최적, 위 40°·아래 20° 가 한계 |
| **SAE AS580** (상용기 조종실 시계 요건) | 같은 계열 | — |
| **F-16** (버블 캐노피) | **15°** | **195°** · 수평 360° · 옆으로 30° |
| **F-35** (틀 있는 캐노피) | **16°** | 188.5° · 수평 340° |
| **우리 배 — 잡았을 때** | **13.4°** | **34.6°** |

★★ **두 가지가 갈린다.**

1. **아래로 보는 각(13.4°)은 거의 맞다.** F-16 이 15°, F-35 가 16°,
   FAA 가 17° 다. v63 에서 계기를 눈 아래로 내린 것이 여기서 값을 했다.
   **조금만 더 내리면 기준에 든다.**
2. **세로 전체(34.6°)가 F-16 의 195° 에 견주면 6분의 1 이다.** 여기가
   「시야가 작다」의 실체다. 그리고 이건 **계기 높이 문제가 아니라
   유리가 멀어서** 생긴다 — 같은 유리도 눈에 가까우면 각이 커진다.

> **왜 거리가 그렇게 센가.** 각도는 `atan(크기 / 거리)` 다. 유리를 두 배
> 키우는 것과 **눈을 유리에 절반만큼 붙이는 것**이 같은 값을 낸다.
> 그런데 유리를 키우면 배가 커지고, 눈을 붙이는 것은 **좌석만 옮기면 된다.**
> F-16 이 「버블」인 이유가 이것이다 — 유리가 큰 게 아니라 **머리 바로 옆**이다.

## 2. 안 셋 — **잰 값으로 견준다**

### 안 ① — 좌석과 콘솔을 **앞으로 0.8m** (권장)

좌석 z −6.95 → **−7.75**, 콘솔 호도 0.55 앞으로. 유리는 그대로.

| | 값 |
|---|---|
| 잡았을 때 유리까지 | **1.37 m** (2.17 에서) |
| 아래 | **15.8°** ← F-16(15°)·FAA(17°) 사이 |
| 위 | 31.5° |
| **세로 창** | **47.3°** (34.6 에서) |
| **화면의** | **50%** (37% 에서) |
| 멀리언 | ±37° (바깥으로 밀려난다) |

**장점** — 조종석 방을 안 늘린다. 좌석·콘솔·조종간이 **한 덩어리로**
움직이므로 v61~v63 에서 맞춰 둔 DEP 관계가 그대로 산다.
**단점** — 50% 다. 「화면을 채운다」까지는 아니다.

### 안 ② — 좌석을 **앞으로 1.35m** + 유리를 위아래로 늘린다 (버블)

좌석 z → **−8.30**, 창 아래끝 0.82 → 0.62, 위끝 2.34 → 2.50, 차양 1.12 → 1.02.

| | 값 |
|---|---|
| 잡았을 때 유리까지 | **0.82 m** — 머리 바로 앞 |
| 아래 | **31.3°** |
| 위 | 50.6° |
| **세로 창** | **81.9°** |
| **화면의** | **87%** |
| 멀리언 | ±52° (거의 안 보인다) |

**장점** — 이게 「전체 화면」이다. F-16 의 버블에 가장 가깝다.
**단점** — 좌석이 **콘솔 호(z −7.95~−8.88) 안쪽**으로 들어간다. 콘솔을
다시 짜야 하고, **계기를 놓을 자리가 준다.** 그리고 조종석 방을
걸어다니는 느낌이 바뀐다 (좌석 뒤가 넓어지고 앞이 없어진다).

### 안 ③ — 12시를 비운다 (①·② 와 **같이** 한다)

스크린샷에서 **창 한복판을 가리는 것이 둘**이다:

- **레이더 화면** — 대시 가운데에 크게 서서 정면을 덮는다
- **천장 리브** — 12시 방향에 세로로 지나간다

실제 전투기는 **12시에 아무것도 안 둔다.** F-16 이 「틀 없는」 캐노피인
이유고, 계기는 전부 시선 아래다. 그래서:

- 레이더를 **대시 아래로 내리거나**, 조종간을 잡으면 **반투명해진다**
- 12시의 구조재를 좌우로 비킨다

**이건 안 ①·② 중 무엇을 골라도 같이 해야 한다.** 창을 아무리 키워도
한복판이 막혀 있으면 넓어진 것이 안 읽힌다.

### 안 ④ — 화각을 창에 맞춘다 (**안 한다**)

화각을 94 → 66 으로 좁히면 창이 화면의 55% 가 된다. 숫자는 좋아지는데
**보이는 하늘의 양은 그대로**다 — 화면만 확대한 것이다. 그리고 v63 이
「좁히는 것이 틀렸다」고 고친 방향과 정면으로 부딪힌다. 적어 두고 안 한다.

그 판정은 숫자가 아니라 **눈**이 하는 것이라 미리 못 정한다.

## 4. ★★ 두 번째 물음 — **「모든 비행 조작은 운전석에 있어야지」**

맞는 말씀이다. 다만 **전부 옮기면 이 게임이 없어진다.** 그래서 선을
어디에 긋는지가 이 절의 전부다.

### 이 게임의 등뼈는 「동시에 두 곳에 못 있는다」 (PLAN §1)

방 일곱을 걸어다니는 것이 이 게임의 몸이다. 조종석에 다 모으면 **의자에서
안 일어나는 게임**이 되고, 그러면 「가는 동안 먹고, 고치고, 뿌리친다」의
가운데 둘이 없어진다.

### 그런데 사장님 말씀도 맞다 — **항로와 추진은 조종 계통이다**

실제 배에서 조타실에 타륜과 기관 텔레그래프가 없으면 그게 이상하다.
지금 항로는 **관측실 해도대**에, 추진은 **통로 차단기**에 있다.

### 그래서 이렇게 가른다 — **「조종」과 「정비」**

| 무엇 | 지금 | 옮기나 | 왜 |
|---|---|---|---|
| **항로 고르기** | 관측실 해도대 | ★ **조종석으로** | 어디로 갈지 정하는 것은 조종이다 |
| **추진 레버(스로틀)** | 통로 차단기 | ★ **조종석으로** | 밟는 것은 조종이다 |
| 조종간 · 자동 항법 | 조종석 | 그대로 | |
| 레이더 · 락온 · 무장 | 조종석 | 그대로 (v64) | |
| **배전 차단기** (추진·냉각·능동 탐지) | 통로 | **안 옮긴다** | 이건 **전기**지 비행이 아니다 |
| 냉각 밸브 · 라디에이터 | 기관실 | **안 옮긴다** | 정비다 |
| 윈치 · 바깥문 · 우주복 · 거래 | 에어록 | **안 옮긴다** | 손으로 하는 일이다 |
| 고장 수리 | 방 일곱 | **안 옮긴다** | 이게 게임이다 |

★★ **차단기를 안 옮기는 것이 이 설계의 핵심이다.**

조종석에 **추진 레버**가 생기면, 밀었는데 안 나가는 일이 생긴다 —
**통로의 추진 차단기가 내려가 있을 때**다. 그러면 계기가 말한다:
「추진 회로가 내려가 있습니다」. 사람은 일어나서 통로로 걸어간다.

즉 **조종은 조종석에서 다 하되, 그것이 되게 만드는 일은 밖에 있다.**
그게 정비공 게임이고, 「비행 조작이 운전석에 있어야지」와도 안 부딪힌다 —
레버는 조종석에 있다.

### 관측실 해도대는 무엇이 되나

**「고르는 곳」에서 「찾는 곳」으로.** 항로 고르기는 조종석으로 가고,
해도대에는 **먼 것을 살피는 일**이 남는다 — 행성 발견 · 구조 신호 ·
거점 정보. 실제 배도 **해도실과 조타실이 다르다.**

> `PLANNING.md §4 ②` 를 또 어겼다 — 기획서의 안② 를 쓸 때 각도만 계산하고

### 12시 — 무엇이 막고 있었나

- **지붕창 리브 `x = 0`** — 정면 한복판을 세로로 가로지르는 구조재였다. 뺐다
- 캐노피 점에는 원래 `x = 0` 이 없었다 (±1.05 가 제일 안쪽) — 지금 ±43도

### ★★★ 레이더 — **판이 아니라 HUD 다**

사장님: 「레이더는 반투명하게 **그 대신 잘 보여야지 조준을 할 수 있겠지?**」

원인이 여기 있었다. 조준경이 **0.78 × 0.58 짜리 불투명 판**으로 앉은 눈
앞 0.77m 에 서 있었고, 계산하면 **37도**를 덮는다. 창의 세로 폭이
34.6도였으니 **창보다 큰 검은 판이 창 앞에** 있었던 셈이다.

「반투명한데 잘 보인다」는 실제 전투기가 이미 푼 문제다 — **HUD** 다:

1. **배경을 안 그린다.** 검은 판이 아니라 **선만 빛난다**
2. **가산 혼합(additive)** — 어두운 픽셀은 아무것도 안 가리고, 어두운
   우주에서는 오히려 더 또렷하다
3. **초록 단색** — 실제 HUD 가 초록인 이유는 사람 눈이 제일 밝게 보는
   색이라서다
4. **표적 위에 얹힌다** — 「화면을 보고 겨눈다」가 아니라
   **「밖을 보면 겨눠져 있다」**가 된다

크기를 **0.78 × 0.58 → 2.2 × 1.55** 로 키우고 앞유리 안쪽에 세웠다.

### ①  가운데 철기둥 — **조종석 파일에 없었다**

v65 에서 「12시를 비웠다」고 적었는데 사장님 화면에는 **여전히 기둥**이
서 있었다. 지운 것은 `world/cockpit.js` 의 지붕 갈빗대였고, 실제로 눈앞을
막고 있던 것은 **`world/ship.js` 의 링 프레임**이었다:

```
ringFrames(ship, r, H, (r.z1-r.z0) >= (r.x1-r.x0) ? 'z' : 'x', 3.2, ...)
```

조종석은 폭 6.8 · 깊이 6.0 이라 `along = 'x'` 로 갈리고, `n = 1` 이라
**딱 한 줄이 `t = 0` 에 선다.** 그리고 그 줄은 앞뒤 벽에 세로 기둥을
세운다 — 즉 **x = 0 · z = −8.95 · 높이 2.7m 의 쇠기둥이 정확히 12시**에.

**진짜 잘못은 「기둥을 안 지웠다」가 아니다.** 조종석의 z0 은 **벽이
아니라 캐노피**다. 벽이 없는 자리에 벽 기둥을 세우고 있었다. `wallRun` 은
조종석 앞을 안 세우는데 `ringFrames` 만 모르고 있었다.

**그리고 `space-view.js [3]` 은 초록이었다.** 캐노피 점의 x 만 봤기
때문이다 — 기둥은 다른 파일에서 서고 있었다. **도구가 나쁜 설계를
지키고 있으면 아무리 돌려도 안 나온다** (이 저장소에서 열여덟 번째다).

### ②  핸들 — **좌우가 창밖에 아예 안 닿는다**

```js
const setAttitude = (a) => { att.pitch = a.pitch ?? 0; att.roll = a.roll ?? 0; };
```

`yaw` 가 **없다.** 조종간 좌우(마우스 X · A/D)는 `fly3.yaw` 를 움직이고,
`fly3.yaw` 는 항로 이탈·잔해 회피·조준 기수각까지 전부 먹인다. 그런데
**창밖 그룹의 `rotation.y` 를 아무도 안 물렸다.** 그래서 좌우로 밀면
숫자는 다 도는데 **별이 한 톨도 안 움직인다.** 사람에게는 「안 먹는다」다.

그리고 하나 더 — `walk()` 에서 A/D 는 `steerPush` 만 덮어쓰고, `flyPush.yaw`
는 그 **윗줄에서 이미 마우스 값으로 정해진 뒤**였다. 즉 **A/D 로는 기수가
안 돈다.** 마우스로만 돌았고, 그 마우스조차 ① 때문에 안 보였다.

### ③  시야 — **각도는 늘었는데 「막힌 것」은 그대로**

## 14. 진짜 배 문제 둘

### ① 땅에 앉은 배가 **엔진을 켠 채**였다

```
땅에 내렸나 true {"step":"landed","ground":true,"thrust":true}
누름 → {"blocked":"thrust","hud":"추진을 끄고 나서 엽니다"}
```

에어록은 `whyNotOpen` 에서 「추진을 끄고 나서 엽니다」로 막는다. 그래서
**바깥문이 영영 안 열렸고**, 내리는 이유가 「싣는 것」인데 실을 수가
없었다. 뜨는 것도 막힌다 — 문을 닫아야 뜨는데 열지도 못했으니까.

**규칙을 무르게 한 것이 아니라 켜 놓을 수 없는 상태를 못박았다** —
착륙한 배의 주 추진은 꺼져 있다 (`lev2 === 'touch'`).

### ② 성간 공백에 **제 구역이 없었다**

`main.js` 는 **매 프레임** 창밖을 `regionOf(route)` 로 되돌린다. 그런데
`regionOf` 는 **갈래만** 보고, 마지막 구간은 **고를 갈래가 없어서**
`forkOf('empty')` 가 그대로 남는다.

이 게임의 목적 한 줄이 「**따라오지 못하는 곳까지 간다**」인데, 정작 거기
도착하면 **창밖이 「빈 공간」**이었다. 말로만 도착한 셈이다.

> ★ 처음에는 도착할 때 `setRegion('void')` 를 한 번 부르는 것으로 고쳤다가
> **다음 프레임에 지워졌다.** 구역은 **한 곳에서** 나와야 한다.

## 15. 그런데 셋은 **검사가 검사를 막고 있었다**

| `[6b]` 이 창밖을 **`empty` 로 못 박고 안 풀었다** (`regionPin`) | `[7] ③④⑤` 가 빨갛고, **게임 버그로 알고 두 번 고쳤다** |

**검사가 검사를 막고 있으면 그 뒤는 아무것도 못 지킨다.** 오늘 세 번이다.

그리고 「**잡히는데 눌린 적이 없다**」가 여러 얼굴로 나왔다 —
누른 시간이 한 프레임보다 짧아서 · 판정 상자 가장자리에 서 있어서 ·
짐벌이 기울어 있어서. 전부 **로그가 「손잡이가 고장났다」와 똑같다.**

## 16. 그래서 검사에 생긴 것들

| 도우미 | 무엇을 막나 |
|---|---|
| `sit()` · `stand()` | 몸이 **다 미끄러질 때까지** 기다린다 — 안 그러면 딴 방에 세워도 되끌려 간다 |
| `settle()` | **짐벌이 바로 설 때까지** (최대 12.6도 기운다 · 헤드리스로 20초) |
| `aimAround()` | 맞는 각도를 **다 모아 가운데**로 — 가장자리에 서면 떨림에 들락날락한다 |
| `pressUntil()` | **안 먹으면 한 번 더 누른다** — 사람이 하는 그것 |

# 던전 상호작용 기획안 — 문 · 함정 · 보물 상자 · 조명 자원화

> 사장: **"던전 문을 연다던가, 함정, 보물 상자등 기획안을 짜줘"**
> 사장: **"몬스터에게 랜턴이나 햇불을 얻을 수 있도록 해줘. 그래서 맵을 밝힐 수 있게"**
> 사장: **"처음 시작시 한개 소지하고"**

대상: `web/3d/` (3D 샘플 「심연의 왕관」)
전제: 외부 에셋 0 — 메시·텍스처·사운드는 전부 코드 생성. 기존 원칙 유지.

---

## 0. 한 줄 진단

**지금 던전에는 「방 사이를 걸어가는 동안 내릴 결정」이 없다.**

현재 층 구조는 `방 → 복도 → 방 → 포탈`이 전부다. 적을 만나면 싸우고, 다 잡으면
포탈이 열린다. 걷는 시간은 그냥 이동 시간이지 판단 시간이 아니다.

문·함정·상자는 걷는 시간을 **판단 시간**으로 바꾸는 장치다. 그리고 그 판단이
성립하려면 **정보가 제한**되어야 한다 — 그게 조명 자원화가 필요한 이유다.

## 1. 조명을 자원으로 만든다 ★ 이게 나머지 셋의 전제다

### 1-1. 지금 문제 — 빛이 공짜라서 어둠이 위협이 아니다

`web/3d/js/world/lighting.js` 를 계측하면:

| 광원 | 현재 값 | 문제 |
|---|---|---|
| 플레이어 등불 | 세기 68 · 반경 **21** · 항상 켜짐 | 어그로 반경(8~12)보다 **훨씬 넓다** |
| 횃불 풀 | 세기 78 · 반경 18 · 8개 고정 | 방 대부분이 이미 밝다 |

플레이어 시야(21)가 적 어그로 반경(8~12)보다 두 배 넓다. **모든 적을 먼저 본다.**
어두운 던전이라고 해놓고 실제로는 정보가 완전 공개인 상태다.

> 이대로 랜턴을 드랍시키면 **아무 의미가 없다.** 이미 다 보이는데 더 밝힐 이유가 없다.
> 랜턴이 보상이 되려면 **기본 시야가 좁아야** 한다. 이 기획의 핵심 전제다.

### 1-2. 변경 — 기본 시야를 어그로 반경 아래로 내린다

| | 현재 | 변경 |
|---|---:|---:|
| 기본 등불 반경 | 21 | **9** |
| 기본 등불 세기 | 68 | **34** |
| 랜턴 소지 시 | — | 아래 표 |

기본 9는 **해골 어그로 8.5 바로 위**다. 랜턴 없이도 「한 마리 끌기」는 가능하되,
망령 궁수(12.5)는 **보이기 전에 나를 먼저 본다.** 어둠이 곧 위험이 된다.

### 1-3. 랜턴 3종

| 이름 | 반경 | 세기 | 연료 | 특성 |
|---|---:|---:|---:|---|
| 낡은 랜턴 | 14 | 52 | 240초 | 시작 지급품 |
| 놋쇠 랜턴 | 18 | 68 | 360초 | — |
| 영혼 등불 | 22 | 80 | 600초 | 벽 너머 적 실루엣이 희미하게 보인다 |

- **연료는 초당 1 소모.** 들고 있는 동안만 준다.
- 연료 0 → **꺼지고 기본 등불로 되돌아간다.** 죽지 않는다.
  벌은 시야지 사망이 아니다 — 어두워졌다고 즉사시키면 그냥 짜증이다.
- **시작 시 「낡은 랜턴」 1개 소지** (사장 지시). 240초는 1층을 도는 데 충분하고
  2층부터는 모자란다 — 보충을 하러 다녀야 하는 압력이 여기서 생긴다.

### 1-4. 어떻게 얻나

| 출처 | 확률 |
|---|---|
| 잡몹 | 4% |
| 망령 궁수 | 9% (등불을 들고 다니는 종족이라는 설정) |
| 정예(무덤 골렘) | 22% |
| 보스 | 확정 1 (영혼 등불) |
| 보물 상자 | 등급별 12~40% |

### 1-5. 연료 보충 — 벽 횃불이 보급소가 된다

이미 층마다 46개씩 배치돼 있는 벽 횃불(`dungeon.js` 의 `torches`)을 그대로 쓴다.

- 횃불 **2유닛 안에서 3초 정지** → 연료 +100
- **횃불 하나당 한 번만.** 쓴 횃불은 사그라든다(불꽃 스프라이트 축소 + 광원 강도 감소)
- 결과: 「밝은 길로 돌아가되, 그 길의 밝기는 내가 써버린 만큼 줄어든다」

### 1-6. 던지는 횃불 (소모품)

- 우클릭으로 **커서 지점에 던진다.** 그 자리를 반경 12로 40초간 밝힌다
- 방에 들어가기 전 **미리 정찰**하는 용도 — 풀링 플레이와 직결된다
- 잡몹 6% 드랍. 최대 5개 소지

### 1-7. 왜 이게 재미있나 — 풀링과 맞물린다

사장이 정한 전투 방식은 **한 마리씩 끌어내는 것**이다. 그런데 지금은 방 전체가
보여서 「어느 놈을 끌지」가 고민이 아니라 그냥 보고 고르면 된다.

기본 시야를 9로 줄이면:

```
어두운 방 앞  →  횃불을 던져 정찰  →  가장자리 한 마리 확인  →  끌어낸다
              ↘ 아끼고 그냥 들어간다 → 두 마리가 동시에 붙을 수도
```

**빛이 정보이고, 정보가 자원이 된다.** 랜턴 연료를 아끼려고 어둠 속에서
싸우다가 궁수를 못 보고 맞는 것 — 이게 이 시스템이 만드는 순간이다.

## 2. 문

### 2-1. 종류

| 종류 | 여는 법 | 역할 |
|---|---|---|
| **평문** | 클릭 (0.4초) | 시야와 소리를 끊는다 |
| **잠긴 문** | 열쇠 필요 | 열쇠를 가진 적을 먼저 찾게 만든다 |
| **봉인문** | 방 안의 적 전멸 | 도망 못 치는 방 — 정예방·보스방 |
| **비밀문** | 밝은 상태에서 벽에 미세한 균열이 보임 | 랜턴을 켤 이유를 하나 더 만든다 |

- **열쇠**는 새 적 「간수」가 떨군다. 층마다 1~2마리, 열쇠를 든 채 순찰한다.
  잘못 끌면 곤란한 놈이 아니라 **찾아서 잡아야 하는 놈**이다.
- 비밀문 뒤에는 상자만 있다. 못 찾아도 진행에 지장이 없다 — 벌이 아니라 보상이다.

### 2-2. 문이 풀링에 하는 일 ★

**닫힌 문은 어그로를 끊는다.** 이게 문의 진짜 기능이다.

- 문 너머의 적은 플레이어를 감지하지 못한다 (`lineOfSight` 에 문을 장애물로 추가)
- 문을 열면 **그 순간부터** 안쪽 적이 어그로 판정을 시작한다
- 즉 **문틈에서 한 마리만 끌어내고 문을 닫는** 플레이가 성립한다

지금의 리쉬(20유닛 귀환)와 합쳐지면: 잘못 끌었을 때 문 뒤로 빠지는 것이
정석 대응이 된다. **도망칠 곳이 생긴다.**

### 2-3. 구현 메모

- 격자에 `DOOR` 셀 종류 추가 (`dungeon.js` 의 `VOID/FLOOR/WALL` 에 이어)
- 열림/닫힘이 `nav.walkable()` 과 `lineOfSight()` 양쪽에 반영돼야 한다
- 문은 방과 복도가 만나는 지점(복도 폭 2칸의 입구)에 놓는다

## 3. 함정

### 3-1. 원칙 — 예고 없는 피해는 넣지 않는다

기존 2D 게임이 v208~v211에서 **무예고 40% → 전 층 0%** 로 끌어내린 원칙을 그대로
따른다(`docs/ART-PLAN-v200.md`, v209 커밋). 3D도 같다: **큰 피해는 전부 지면 예고가 먼저.**

함정의 예고는 두 겹이다.

1. **발견 단계** — 밝으면 바닥에 미세한 표식이 보인다 (어두우면 안 보인다 ← 랜턴)
2. **발동 단계** — 밟은 뒤 실제 피해까지 지연이 있다 (0.4~0.8초, 붉은 예고)

### 3-2. 종류

| 함정 | 발동 | 피해 | 회피 |
|---|---|---|---|
| 압력판 가시 | 밟으면 0.5초 뒤 | 최대 체력 12% | 예고 원 밖으로 |
| 화살 발사기 | 선을 지나면 즉시 발사 | 8% + 넉백 | 발사선이 바닥에 그려진다 |
| 낙석 | 밟으면 0.8초 뒤 | 18% + 기절 0.6초 | 그림자가 먼저 커진다 |
| 바닥 붕괴 | 밟으면 0.6초 뒤 | 아래층으로 낙하 (10% + 위치 이동) | 균열이 먼저 벌어진다 |
| 독가스 | 밟으면 즉시 | 초당 3% (장판 8초) | 장판 밖으로 |

### 3-3. 함정은 적에게도 작동한다 ★

이게 함정을 「장애물」에서 「도구」로 바꾼다.

- 끌어낸 적을 **함정 위로 유인**해서 밟히게 할 수 있다
- 골렘(넉백 면역·느림)처럼 정면으로 버거운 적을 함정으로 깎는 판단이 생긴다
- 풀링 방식과 정확히 같은 결의 재미다 — **위치를 고르는 것이 전투다**

### 3-4. 해제

- 발견한 함정을 클릭하면 2초간 해제 시도. 성공 시 경험치 소량
- 실패 확률 없음 — 도박이 아니라 **시간 대 안전의 교환**이다

## 4. 보물 상자

### 4-1. 종류

| 상자 | 조건 | 내용물 | 위험 |
|---|---|---|---|
| **나무 궤** | 없음 | 일반~마법 1개 | — |
| **철제 궤** | 잠김 (열쇠 또는 2초 강제 개봉) | 마법~희귀 1~2개 | 강제 개봉 시 소음 → 주변 적 어그로 |
| **봉인된 관** | 없음 | 희귀~전설 2개 | **미믹 확률 25%** |
| **저주받은 궤** | 최대 체력 25% 지불 | 전설 확정 1개 | 지불한 체력은 층을 넘어야 회복 |

### 4-2. 미믹

- 「봉인된 관」이 25% 확률로 적으로 변한다
- **예고**: 열기 전 관이 **미세하게 흔들린다**(주기 0.3초, 진폭 작음).
  주의 깊게 보면 알 수 있되, 대충 보면 놓친다 — 관찰에 대한 보상
- 미믹은 정예급(골렘 수준 HP·넉백 면역), 처치 시 전설 확정

### 4-3. 배치

- 방마다 **최대 1개**. 층당 3~5개
- 비밀문 뒤에는 반드시 「봉인된 관」 또는 「저주받은 궤」
- 보스룸에 확정 1개 (보스 처치 후 개봉 가능)

### 4-4. 왜 저주받은 궤인가

기존 2D 기획안(`docs/GAME_DESIGN.md` §2-4 「의미 있는 선택과 리스크」)이 세운
**"체력을 지불하는 계약"** 을 3D에 그대로 가져온다. 지금 3D 샘플에는
리스크를 지는 선택지가 하나도 없다 — 강해지는 길이 전투 하나뿐이다.

## 5. 넷이 어떻게 하나로 맞물리는가

따로 노는 기능 넷이 아니다. **하나의 루프**다.

```
어둡다 (기본 시야 9)
   │
   ├─ 랜턴을 켠다 → 연료가 준다 → 벽 횃불로 보충하러 가야 한다
   │                                    ↑ 그 횃불은 쓰면 사그라든다
   ├─ 밝으니 바닥의 함정 표식이 보인다 → 피하거나, 적을 그리로 유인한다
   │
   ├─ 밝으니 벽의 비밀문 균열이 보인다 → 상자
   │
   └─ 문을 연다 → 그 순간 안쪽 적이 나를 인지한다
          │
          └─ 한 마리만 끌고 문 뒤로 빠진다 (리쉬 + 문이 어그로를 끊는다)
```

**모든 화살표가 「빛」에서 나온다.** 그래서 §1이 나머지의 전제다.

## 6. 구현 순서 — 각 단계가 독립적으로 검증 가능하게

| 단계 | 내용 | 검증 |
|---|---|---|
| **1** | 조명 자원화 — 기본 시야 축소, 랜턴 3종, 연료, 시작 지급 | 시야 반경이 어그로 반경 아래인가 · 연료 0에서 기본 등불로 복귀하는가 |
| **2** | 벽 횃불 보충 + 던지는 횃불 | 횃불당 1회만 보충되는가 · 던진 횃불이 광원 풀을 넘지 않는가 |
| **3** | 문 (평문·봉인문) — 격자·길찾기·시야 차단 | 닫힌 문이 `lineOfSight` 를 막는가 · 문 뒤 적이 어그로 안 붙는가 |
| **4** | 잠긴 문 + 간수 + 열쇠 | 열쇠 없이 못 여는가 · 간수가 층마다 존재하는가 |
| **5** | 함정 5종 — 발견·예고·발동·해제 | **무예고 피해 0건** · 적도 밟는가 |
| **6** | 상자 4종 + 미믹 | 미믹 예고가 개봉 전에 보이는가 · 등급별 드랍이 표에 맞는가 |
| **7** | 비밀문 | 밝을 때만 보이는가 |

단계 1~2가 나머지의 전제이므로 **먼저 넣고 실제로 플레이해서** 어둠이
답답한지 재미있는지부터 확인한다. 답답하면 기본 반경 9를 11~12로 올린다.

## 7. 검증에 추가할 항목 (`tools/verify3d.js`)

```
light.baseRadiusBelowAggro   기본 시야가 해골 어그로보다 좁은가
light.lanternExtends         랜턴을 들면 반경·세기가 커지는가
light.fuelDrains             연료가 초당 1 줄고 0에서 기본 등불로 복귀하는가
light.startsWithLantern      시작 시 낡은 랜턴 1개를 소지하는가
light.poolStillFixed         던진 횃불이 늘어도 광원 개수가 고정인가 ★
door.blocksSight             닫힌 문이 시야를 막는가
door.blocksAggro             문 뒤 적에게 어그로가 안 붙는가
door.lockedNeedsKey          열쇠 없이 잠긴 문이 안 열리는가
trap.alwaysTelegraphed       무예고 피해 0건 (전 층 전수)
trap.hitsEnemies             적도 함정에 걸리는가
chest.mimicTelegraphed       미믹이 개봉 전에 흔들리는가
chest.lootMatchesTable       등급별 드랍이 표대로인가
```

★ **`light.poolStillFixed` 가 이 중 가장 중요하다.** three.js 는 씬의 광원
**개수**가 바뀌면 셰이더를 재컴파일해서 프레임이 끊긴다. 지금은 횃불 8개 고정
풀로 이 문제를 피하고 있다(`lighting.js`). 던지는 횃불을 넣을 때 광원을
새로 만들면 **그 순간 화면이 멈춘다.** 반드시 기존 풀을 재사용해야 한다.

## 8. 컴펌 받을 것

1. **기본 시야를 21 → 9 로 줄이는 것** — 이 기획의 전제다. 어두워지는 게 싫으시면
   랜턴은 「더 밝게」가 아니라 「반경은 그대로, 대신 함정·비밀문이 보인다」로
   바꿔야 한다. 어느 쪽입니까?
2. **연료 관리를 넣을지** — 넣으면 긴장이 생기지만 관리 부담도 생긴다.
   빼면 랜턴은 그냥 한 번 먹고 끝인 영구 강화가 된다.
3. **저주받은 궤(체력 지불)** — 리스크 선택지를 넣을지
4. **미믹 25%** — 상자를 열 때마다 긴장할지, 아니면 상자는 순수 보상으로 둘지
5. **구현 순서** — 1~2단계(조명)를 먼저 넣고 플레이해 본 뒤 나머지를 정하는 것이 맞습니까?

## 9. 이 문서가 다루지 않은 것

- **미술**: 문·상자·함정의 메시는 B안(노멀맵 기반) 규격을 따른다는 것 외에 정하지 않았다
- **사운드**: 문 삐걱임·함정 발동·상자 개봉 — 절차 합성으로 만들 수 있으나 설계 안 함
- **성능**: 문이 `lineOfSight` 호출마다 추가 검사를 하게 되는데, 적 26마리가
  매 프레임 호출하는 경로다. 실측 없이 「괜찮을 것」이라고 적지 않는다 — 구현 시 계측한다

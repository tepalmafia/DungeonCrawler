## 2. 설계 원칙 6조 (군중 제압 학파 규격)

1. **손맛의 단위는 「타격」이 아니라 「스윙의 결과」다.** 한 번 휘두른 결과(몇 대 맞고 몇이 죽었는가)를 프레임 끝에 정산해서 **한 번의 연출**로 낸다. 9마리를 벤 스윙과 1마리를 친 스윙이 손에서 달라야 한다.
2. **죽이는 것이 때리는 것보다 항상 크다.** 히트스톱·셰이크·소리 예산을 처치 쪽에 몰아준다. 현재는 40ms = 40ms로 완전히 같다.
3. **회피는 위치 선정이다.** 0.25초짜리 반응 테스트를 개선하지 말고, **어디에 서 있는가**를 지표로 만들어 화면에 띄운다.
4. **위협은 개체가 아니라 배치에서 나온다.** 적 HP를 올리지 않는다(성장 무효화의 재발). 대신 **몇이 나를 둘러쌌는가**가 무적 시간을 깎는다.
5. **연출 예산은 플레이어의 성공 쪽이 실패 쪽보다 커야 한다.** 현재 1 : 4.9 (때릴 때 1.42px : 맞을 때 7.0px). 목표 **1.2 : 1**.
6. **화면은 960×540 고정으로 남는다.** 카메라를 만들지 않는다. 대신 「이동」은 방 전환 순간에만 임시 오프셋으로 표현한다. (비용 근거 §6.1)

### 3.1 타격 정산기 (Strike Ledger) — 이 기획의 중심 장치

**문제** `[실측]`: `combat.js:292`(타격 40ms, 게이트 0.11초)와 `combat.js:450`(처치 65ms, 게이트 0.06초)가 **같은 프레임에 서로를 막는다**. 검으로 벤 처치가 40ms가 되고, 손도 안 댄 장판 처치가 65ms를 받는다. 광역으로 9마리를 죽여도 히트스톱은 1회분이고, 소리는 게이트에 잘리고, 화면은 1.42px 흔들린다.

**처방**: 개별 타격이 히트스톱·셰이크·사운드를 **직접 호출하지 않는다.** 한 프레임 동안 장부에 적립하고 프레임 끝에 한 번 정산한다.

### 3.2 셰이크 엔진 — 코드에 적은 숫자를 화면에 도달시킨다

**문제** `[실측]`: `core/renderer.js:33` `m = _shakeMag * Math.min(1, _shakeDur * 5)` — 지속이 0.2초 미만이면 램프업 계수가 1에 못 닿는다. 전투 셰이크 전부(0.12~0.16초)가 이 구간이라 **2.5px로 적은 것이 화면에는 1.42px로 나온다**(57%). 게다가 `renderer.js:22`의 `mag >= _shakeMag` 규칙 탓에 피격(7×0.35s) 직후 367ms 동안 내 타격 셰이크가 통째로 삼켜진다.

**처방** (`core/renderer.js`, `shake()` + `update()`, 약 10줄)

| 항목 | 현재 | 변경 |
|---|---|---|
| 포락선 | `min(1, dur*5)` 램프업 | `_shakeDur0` 저장 후 `m = mag * (dur/dur0)` **선형 감쇠** — 1프레임째가 최대 진폭 |
| 우선순위 | `mag >= _shakeMag` (진폭 비교) | `mag*dur >= _shakeMag*_shakeDur` **에너지 비교** — 짧고 강한 타격이 길고 약한 잔여를 이긴다 |
| 결과 (타격 3.0×0.20) | 실효 1.42px | **실효 3.0px (2.1배)**, 12프레임 중 9프레임 ≠0 |

검증 영향: 셰이크를 재는 회귀 항목은 **0개** (109항목 전수 확인). 위험 없음.

**추가 — 넉백 전파 (군중 제압 학파의 서명 기술, 약 15줄)**
밀려나는 적이 다른 적과 겹치면 그 적도 **원 넉백의 0.40배**로 함께 밀린다(연쇄 최대 2단, 1회 타격당 1회만). 9마리를 친 마무리가 화면에서 **볼링처럼 무리를 무너뜨린다.** `play.js` 분리력 블록(129~152행) 옆에 붙인다.

**분리력 강화** (선결 조건, §1-③): 현재 밀어내는 속도 `e.speed*0.8` → **`e.speed*1.6` + 최소 1.2px/frame 바닥값**. 30마리 밀집 최소 간격 3.6px → 목표 **18px 이상**. 검증 `separation.pushesApart`는 강화 방향이므로 통과.

### 3.5 처형 임계와 처형 연쇄 — 「끝냈다」의 문법

군중 제압 학파의 손맛은 **마지막 한 대**에서 온다. 적 HP를 낮추지 않고(§원칙 4) 마지막 한 대를 특별하게 만든다.

| 규격 | 값 (설계) |
|---|---|
| 빈사 조건 | 잡몹(비보스·비우두머리) `hp ≤ maxHp×0.30` **또는** `hp ≤ 2` |
| 빈사 표시 | 백색 윤곽 점멸 2Hz + 머리 위 쐐기 마커 (§3.3) |
| 처형 | 빈사 적에 **어떤 근접·대시파생·스킬 타격이든 닿으면 즉사** (피해 계산 생략) |
| 처형 연쇄 | 처형 지점 반경 **84px** 안의 빈사 적 최대 **3기** 추가 처형, 0.05초 간격 |
| 처형 연출 | 처형 1건당 붉은 쐐기 섬광 + `AudioSys.execute()`(신설) + 정산기에 `kill` 적립 |
| 보상 | 처형 연쇄 2기 이상 → **대시 재충전 +0.5**, 궁극 게이지 +2 (기본 1) |
| 보스 연동 | 처형 연쇄 1회 = 방 안 보스 **경직 게이지 +8%** (§3.6) |

**왜 이게 결정적인가**: 지금 정산기가 6킬을 한 번에 뽑으려면 광역 피해량이 필요한데, 그러면 성장 곡선이 무너진다. 처형 임계는 **피해량을 건드리지 않고** 「무리를 골고루 깎은 뒤 한 번에 정리한다」는 **행위**를 만든다. 그게 이 학파의 핵심 결정이다: *지금 쓸어버릴까, 한 번 더 깎을까.* 방 하나 11.9초 동안 결정 0개였던 자리에 **초당 1회의 결정**이 들어온다.

기존 자산과의 정합: 특성 `execeye` 「처형인의 눈」(HP 30% 이하 +2 피해, `traits.js:177`)이 이미 **같은 임계선 30%**를 쓴다. 이 특성은 처형 임계를 **40%로 넓히는** 것으로 승격한다(문구 변경 1줄).

### 3.6 보스 — 경직 게이지 (넉백 1.64px의 대안)

| 항목 | 값 (설계) |
|---|---|
| 경직 게이지 | `poise = maxHp × 0.34` (보스전당 약 3회 발동) |
| 충전 | 보스에게 준 피해 + 처형 연쇄 1회당 `maxHp×0.027` |
| 발동 | 보스 0.55초 무방비(`stagger`) + 히트스톱 **150ms** + 셰이크 8×0.35 + 「무너뜨렸다」 + 이 동안 피해 ×1.4 |
| 파일 | `boss.js` 피격 경로 + `combat.js damageEnemy` 보스 분기 (약 30줄) |

보스전 30~120타 동안 세계가 한 번도 안 멈추던 것 `[실측]` → **3회의 정지 + 3회의 확정 딜 창**. 그리고 그 게이지를 **잡몹 처형으로도 채울 수 있다** = 보스전에 군중 제압이 들어온다.

## 4. 축 ② 회피 — 타이밍이 아니라 자리

### 4.1 진단 재정의

v188이 예고를 0.42초로 늘린 것은 옳다(반응 250ms + 여유 170ms). 하지만 그것만으로는 **회피가 25초에 한 번 있는 사건**이라는 구조가 안 바뀐다. 실측이 말한 것: 대시 공급 0.67회/초 vs 접촉 예고 수요 1.4~3.8회/초 — **개별 공격을 하나씩 피하는 게임은 산술적으로 성립하지 않는다.**

군중 제압 학파의 답: **개별 공격을 피하지 마라. 무리 전체에 대해 자리를 잡아라.**

### 4.2 포위도 (Encirclement) — 새 지표, 화면에 상시 표시

```
매 프레임, 플레이어 기준:
  n     = 반경 120px 안의 적대 개체 수
  cover = 8방위 비트마스크의 채워진 방위 수 × 45°
  tier  = 아래 표
```
비용: O(적 수). 64마리에서 0.044~0.069ms 여유 안 (§1 실측).

| 등급 | 조건 | 화면 | 피격 후 무적 배율 | 접촉 예고 | 접촉 피해 |
|---|---|---|---|---|---|
| 0 평상 | n ≤ 1 | — | ×1.00 | 0.42s | 1 |
| 1 **둘러싸임** | n 2~3 또는 cover ≥ 180° | 플레이어 주변 얇은 호(황색 #d9a441), 적이 있는 방위만 | ×0.85 | 0.42s | 1 |
| 2 **포위** | n 4~5 또는 cover ≥ 270° | 호 주황 #ff7043 + 맥동 | ×0.70 | **0.36s** | 1 |
| 3 **매몰** | n ≥ 6 또는 cover ≥ 315° | 호 적색 #e43b44 + 심장박동음 0.9Hz + 비네트 0.35 | ×0.55 | **0.32s** | **2** |

파일: `play.js _tickPlay()` 계산 25줄 / `ui/render-game.js` 호 렌더 25줄 / `core/audio.js` 심박음 12줄.

**이 하나로 ②와 ③이 동시에 해결된다.** 회피는 "지금 구를까"가 아니라 **"이 자리에 더 있어도 되는가"**가 되고, 난이도는 "적이 세다"가 아니라 **"내가 잘못 섰다"**가 된다. 그리고 화면에 등급이 떠 있으므로 **죽음의 원인이 항상 내 탓으로 읽힌다.**

### 4.3 돌파 (Breakout) — "내가 피했다"를 방당 3~6회로

| 규격 | 값 (설계) |
|---|---|
| 조건 | 등급 2 이상에서 **0.45초 안에** 등급 0으로 내려감 (대시·회전베기·넉백 무엇으로든) |
| 보상 | 「돌파!」 20px + 슬로모 0.22초(×0.55) + 청록 섬광 + 대시 재충전 **+0.6** + **다음 일격 확정 크리** (기존 `pdodgeCrit` 재사용) |
| 사운드 | 기존 완벽회피음 + 저역 1겹 |
| 파일 | `play.js` 포위도 블록 하단 (12줄), `combat.js:783` 완벽회피 분기 재사용 |

목표 빈도: **8~12초에 1회** (현재 완벽 회피 `[실측]` 24.6초에 1회, 휴먼 봇 80초에 1회).

### 6.4 ★ 파도가 문에서 들어온다 — 맵과 전투를 하나로 묶는 유일한 장치

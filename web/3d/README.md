# 심연의 왕관 (Deep Crown) — 3D 액션 RPG 샘플

디아블로류 쿼터뷰 액션 RPG의 **수직 슬라이스**입니다.
기존 2D 게임(`web/`)과는 완전히 분리된 별도 샘플이며, 기존 코드는 한 줄도 건드리지 않습니다.

플레이: <https://tepalmafia.github.io/DungeonCrawler/3d/>

```
1층 → 2층 → 3층(보스: 심연의 군주) → 처치 → 다음 회차(파밍 티어 +1)
                    ↓ 사망
              장비 유지한 채 1층부터 다시
```

## 실행

**ES 모듈이라 `file://` 로는 열리지 않습니다.** 반드시 정적 서버로 띄우세요.

```bash
python3 tools/serve.py 8137     # 저장소 루트에서
# → http://127.0.0.1:8137/3d/
```

빌드 단계는 없습니다. 파일을 저장하고 새로고침하면 끝입니다.

## 조작

| 입력 | 동작 |
|---|---|
| **좌클릭** | 이동. 누르고 있으면 커서를 계속 따라간다 |
| **적 좌클릭** | 사거리까지 접근 후 자동 평타 반복 |
| **바닥 아이템 클릭** | 그 자리로 이동해 획득 |
| **Q** | 회전 베기 — 전방 부채꼴 광역 (마나 12) |
| **W** | 그림자 돌진 — 커서 방향 돌진, 돌진 중 무적 (마나 20) |
| **E** | 화염 신성 — 주변 폭발 + 장판 (마나 35) |
| **R** | 운석 낙하 — 지정 지점에 예고 후 착탄 (마나 60) |
| **1 / 2** | 체력 / 마나 물약 |
| **I** | 인벤토리 (Esc 로도 닫힘) |
| **Alt** (누르고 있기) | 바닥 아이템 이름 전부 표시 |
| **벽 횃불 옆에 3초 정지** | 랜턴 연료 +100초 (횃불 하나당 한 번) |
| **마우스 휠** | 줌 인 / 아웃 (카메라 거리 10~34) |
| **+ / −** | 키보드 줌 (휠 없는 환경용) |
| **0** | 줌 기본값으로 |

HUD 는 **체력 구슬 – 단축키 2줄 – 마나 구슬** 을 화면 하단 중앙에 나란히 둡니다.
전투 중 시선이 화면 양쪽 끝까지 갈 필요가 없게 한 배치입니다.

## 전투 — 한 마리씩 끌어와 1대1로 잡는다

몰려오는 무리를 광역기로 쓸어담는 게임이 아닙니다. **가장자리 한 마리에게만 다가가
그놈만 끌어내고, 시간을 들여 확실히 잡은 뒤 다음 한 마리로 넘어가는** 방식입니다.
그래서 규칙이 이렇게 짜여 있습니다.

- **어그로는 개체별로만 붙는다.** 한 마리가 반응해도 옆의 동료에게 번지지 않습니다.
- **어그로 반경이 좁다** (8~9 유닛). 궁수만 12.5로 넓어서, 잘못 끌면 곤란해집니다.
- **개체 HP가 높다.** 한 판이 짧지 않습니다. 레벨 1·초기 무기로 실측한
  순수 처치 시간은 **구울 6.7초 · 해골 10.0초 · 골렘 39.6초**입니다
  (회피·재접근 시간은 뺀 값이니 실제 체감은 더 깁니다).
- **리쉬가 있다.** 원래 자리에서 20 유닛 넘게 끌려나오면 제자리로 돌아가며 회복합니다.
  여러 마리를 달고 도망다니는 플레이를 막는 장치이자, 잘못 끈 적을 떼어내는 안전장치입니다.
- **배치가 흩어져 있다.** 적끼리 최소 6.5 유닛 간격으로 놓여, 어느 놈부터 끌지 고를 수 있습니다.
- 어그로가 붙는 순간 **발밑에 붉은 원**이 한 번 번집니다 — 어느 놈이 반응했는지 즉시 보여야 합니다.

| 이름 | 어그로 | 특징 |
|---|---:|---|
| 해골 병사 | 8.5 | 기본 근접. 예비 동작이 길어 보고 피할 수 있다 |
| 구울 | 9.5 | 빠르고 약함. 주기적으로 도약 돌진 |
| 망령 궁수 | **12.5** | 원거리 투사체. 가까이 가면 물러난다. **먼저 반응하므로 동선을 먼저 계산해야 한다** |
| 무덤 골렘 (정예) | 8 | 육중·넉백 면역. 지면 강타 — **붉은 예고 원 밖으로 나가야 한다**. 아이템 확정 드랍 |
| **심연의 군주** (보스) | — | 1페이즈 광역 베기·연타·돌진 → 2페이즈 소환·화염 원 → 3페이즈 회전 광선·격노 |

큰 기술은 **전부 지면 예고가 먼저** 뜹니다. 보고 피할 수 있어야 한다는 원칙입니다.
(보스가 소환한 적은 리쉬가 없습니다 — 보스전은 끌어내는 싸움이 아니니까요.)

### 템포

한 합 한 합이 눈에 읽혀야 「신중하게 끌어와 잡는」 플레이가 성립합니다. 그래서
공격·이동 속도를 기준값보다 **30% 낮춰** 두었습니다. 조절은 `js/game/pace.js`
한 파일에서 합니다 — 플레이어·잡몹·보스가 같이 움직입니다.

| 상수 | 값 | 뜻 |
|---|---:|---|
| `MOVE_SCALE` | 0.7 | 걷기·추격·돌진·도약 |
| `ATTACK_SCALE` | 0.7 | 초당 공격 횟수, 선딜·후딜 진행 속도 |
| `ATTACK_TIME` | 1/0.7 | 「초」로 적힌 값(예고 링 지속·쿨다운)에 곱하는 환산 계수 |

레벨 1·초기 무기 기준 실측: 초당 공격 0.89 → **0.62회**, 이동 6.2 → **4.34 유닛/초**.
처치 시간은 그만큼 늘어납니다 (해골 7.0 → 10.0초, 골렘 27.7 → 39.6초).

개별 수치(`BASE_SPEED`, 종족별 `speed`, `windup`/`recover`)는 **서로의 차이**를,
이 배수는 **전체 템포**를 담당합니다. 섞지 않아야 조정이 쉽습니다. 시간으로 적힌
값에 속도 배수를 그대로 곱하면 예고 링이 타격보다 먼저 꺼져 **예고 없이 맞는**
버그가 됩니다 — 그래서 `pace.windupMatchesTelegraph` 검사가 선딜을 실측합니다.

## 빛이 자원이다 — 랜턴

**기본 시야는 반경 9**로, 망령 궁수의 어그로 반경(12.5)보다 좁습니다.
즉 **궁수는 내가 보기 전에 나를 먼저 봅니다.** 어둠이 실제 위험입니다.

| 랜턴 | 반경 | 연료 | 비고 |
|---|---:|---:|---|
| 낡은 랜턴 | 14 | 240초 | **시작 지급품** |
| 놋쇠 랜턴 | 18 | 360초 | — |
| 영혼 등불 | 22 | 600초 | 보스 확정 드랍 |

- **연료는 들고 있는 동안 초당 1 소모.** 다 타면 꺼지고 기본 등불로 돌아갑니다 — 죽지는 않습니다.
- 몬스터가 떨굽니다: 잡몹 4% · 망령 궁수 9% · 정예 22% · 보스 확정
- **여분 랜턴은 쌓이지 않고 기름이 됩니다.** 더 좋은 걸 주우면 바꿔 들고, 같거나 못하면 연료로 들어갑니다
- **벽 횃불 옆에 3초 서 있으면 연료 +100초.** 단 그 횃불은 사그라듭니다 —
  지나온 길이 어두워지는 게 대가입니다

시작 240초는 1층을 도는 데 충분하고 2층부터는 모자랍니다. 보충하러 다녀야 하는
압력이 여기서 생깁니다. 설계 근거는 `docs/DUNGEON-INTERACTIONS.md` §1.

## 아이템

등급 4종 — 일반(회색) · 마법(파랑) · 희귀(노랑) · 전설(주황).
등급이 오를수록 접사가 1→4개 늘고, 값은 층수와 파밍 회차에 비례해 커집니다.
슬롯은 무기 / 방어구 / 반지 3칸이며, 장착 즉시 스탯이 재계산됩니다.
가방에서 호버하면 착용 중인 장비와 종합 점수를 비교해 줍니다.

## 테스트 훅

기존 2D 게임과 같은 규약을 씁니다.

- `?seed=ABC123` — 시드 지정 (같은 시드 = 같은 던전)
- `?floor=N` — N층부터 시작 (1~3)
- `?jump=boss` — 보스룸 근처에서 시작 (`floor=3` 과 조합)
- `?ff=N` — N배속 (1~8)
- `?bot=1` — 자동 플레이 (자동 시작 포함)
- `?autostart=1` — 타이틀 화면 건너뛰기
- `window.G3` — 콘솔에서 게임 상태 전체 확인

예: `?bot=1&ff=4&seed=TEST1` — 4배속 봇이 어디까지 가는지 관찰

## 기술 메모

- **카메라**: 원근(FOV 30°, 거리 19, 피치 52°). 직교 대신 좁은 FOV 원근을 쓴 이유는 벽 높이와 횃불 감쇠가 읽혀야 "던전 안"이 되기 때문입니다.
- **조명**: three.js에서 PointLight 그림자는 큐브맵 6패스라 여러 개를 켤 수 없고, 씬의 광원 *개수*가 바뀌면 셰이더가 재컴파일되어 프레임이 끊깁니다. 그래서 그림자 캐스터는 **DirectionalLight 1개**뿐이고, 횃불은 **개수가 고정된 8개 풀**을 재사용하며 위치·강도만 바꿉니다. 접지감은 모든 엔티티의 발밑 블롭 그림자가 담당합니다.
- **앰비언트를 낮게 유지합니다**(0.26). 이게 높으면 랜턴이 없어도 방이 다 보여서 빛이 자원이 되지 못합니다. B안의 표면 요철은 횃불·랜턴이 만드는 밝은 웅덩이 안에서 드러나면 되고, 오히려 그쪽이 더 극적입니다.
- **r185는 물리 조명 단위**입니다(`useLegacyLights` 제거). PointLight intensity는 20~60 / `decay = 2` 가 기준이고, 예전 감각인 1.0을 쓰면 화면이 새까맣게 나옵니다.
- **드로우콜**: 바닥은 바닥 칸만 모은 단일 지오메트리, 벽·소품은 `InstancedMesh` — 층 전체가 10콜 남짓입니다.
- **벽 투명화**: 쿼터뷰는 벽 뒤로 들어가면 캐릭터가 통째로 가려집니다. 카메라–캐릭터 선분과 교차하는 벽·기둥을 흐리는데, **알파 블렌딩이 아니라 정렬 디더(Bayer 8×8) discard** 를 씁니다 — 투명 처리를 하면 벽끼리·소품과 정렬이 틀어져 더 큰 문제가 생기고, 디더는 깊이 버퍼를 그대로 써서 정렬 문제가 아예 없습니다. 주의: 페이드 재질을 쓰는 `InstancedMesh` 에 `aFade` 속성이 없으면 셰이더가 0을 읽어 **그 메시가 통째로 사라집니다** (검증 `occlusion.attrOnFadeableMesh` 가 막습니다).
- **포스트프로세싱 없음**: `ACESFilmicToneMapping` + CSS 비네트 오버레이로 대체했습니다(애드온 의존 0).
